# 광고 캠페인 주간 리포트 — 사례 실습 데이터

> 교육 사이트 **2차시(지식을 파일로)** 사례의 실제 입력 데이터입니다.
> 5차시(출력 계약)·6차시(계산은 도구에게) 사례의 재료도 여기서 나옵니다.
> 등장하는 회사·브랜드·수치는 모두 **가상**입니다.

## 1. 상황

광고대행사 AE **정하늘 대리**는 매주 월요일, 5개 매체에서 성과 파일을 받아
광고주 제출용 주간 리포트를 만듭니다. 매주 2시간 30분이 걸립니다.

양식은 매체가 정해 주는 대로 받는데, **컬럼명·지표 정의·통화 기준이 전부 다릅니다.**

## 2. 파일 구성

```
ad/
├── README.md                    ← 본 문서
├── data/                        ← 입력: 매체별 성과 파일 5개 (2026-07 3주차)
│   ├── 2026-07-W3_네이버GFA.csv
│   ├── 2026-07-W3_카카오모먼트.csv
│   ├── 2026-07-W3_메타.csv
│   ├── 2026-07-W3_구글애즈.csv
│   └── 2026-07-W3_틱톡.csv
├── 매체_표준용어집.md              ← 지식 베이스 (2차시 사례의 결과물)
└── prompt.md                    ← 에이전트 지시서
```

## 3. 매체별로 무엇이 다른가

| 매체 | 노출 컬럼 | 집행액 | 날짜 | 특이사항 |
|---|---|---|---|---|
| 네이버GFA | `노출수` | 광고비 **VAT별도** | `2026-07-13` | 표준에 가장 가까움 |
| 카카오모먼트 | `노출` | 소진금액 **VAT포함** | `26.7.13` | **VAT 환산 필요** |
| 메타 | `Impressions` | `Amount spent (KRW)` | `2026-07-13` | **`Results` 의 뜻이 목적에 따라 다름** |
| 구글애즈 | `Impr.` | `Cost` | `2026/07/13` | 영문 약어 |
| 틱톡 | `Imp` | `Spend` | `20260713` | KPI 약어 · 노출 640 짜리 테스트 캠페인 포함 |

### 데이터에 심어 둔 함정 네 가지

| 함정 | 용어집 없이 통합하면 (실측) |
|---|---|
| 카카오 **VAT 포함** | 집행액이 10% 크게 잡혀 **카카오 ROAS 310.3% → 282.1%** (28.2%p 낮게). 성과를 실제보다 나쁘게 보고 |
| 메타 **`Results`** — `Link clicks` 목적 행의 값은 클릭수 | 메타 전환 **565건 → 5,308건 (9.4배)**, CPA **18,956원 → 2,018원**. 전체 전환도 2,085 → 6,828건(3.3배) |
| 날짜 **3가지 형식** | 주차 집계가 어긋난다 |
| 틱톡 **노출 640** 테스트 캠페인 | 전환 0인데 CTR 1.72% 로 효율이 좋아 보인다 |

> 위 숫자는 이 데이터로 직접 계산해 확인한 값입니다. 실습 후 본인 결과와 대조해 보세요.

이 네 가지가 **정하늘 대리 머릿속에만 있던 규칙**이고, 그것을 파일로 꺼낸 것이
`매체_표준용어집.md` 입니다.

## 4. 실습 방법

### A. 용어집 없이 먼저 (2차시 실습 A에 해당)

```
cd ad          # Windows: cd C:\harness-edu\ad
claude
```

입력창에:

```
data 폴더의 매체별 성과 파일 5개를 하나로 통합해서 주간 리포트를 만들어줘.
```

**관찰 포인트**: 두 번 돌려 보세요. 매체명 표기·전환 정의·VAT 처리가 회차마다
달라지고, 위 네 가지 함정 중 최소 두 개가 조용히 틀립니다.

### B. 용어집과 함께 (2차시 실습 B에 해당)

```
이 폴더의 prompt.md 를 읽고, 거기 적힌 절차대로 수행해줘.
```

**검수 체크리스트**

- [ ] 카카오 집행액이 VAT 별도로 환산되었는가 (÷1.1)
- [ ] 메타 `Link clicks` 목적 행의 전환이 **0** 으로 처리되었는가
- [ ] 날짜가 모두 `YYYY-MM-DD` 인가
- [ ] `Lumiere_Spark_Test` 가 **데이터 부족** 으로 표시되었는가
- [ ] ROAS 가 매체 리포트 값이 아니라 **재계산 값**인가
- [ ] 정규화 이력(어느 컬럼을 무엇으로 매핑했는지)이 보고되었는가

## 5. 뒤 차시와의 연결

| 차시 | 이 데이터로 하는 것 |
|---|---|
| **2차시** | 용어집(Skill)을 파일로 꺼내면 결과가 안정되는 것을 확인 |
| **4차시** | 이 업무의 에이전트 팀 구성 (정규화 / 분석 / 이슈 / 집필 / 검증) |
| **5차시** | 리포트 항목을 **출력 계약**으로 고정 (매체 5개·이슈등급 3단계·다음행동 필수) |
| **6차시** | CPA·ROAS 재계산을 **Tool** 로 옮기기 — 설명서로 시키면 VAT 처리를 빠뜨린다 |

> 6차시 포인트: 위 재계산 규칙은 용어집(설명서)에 적어 두어도 모델이 **암산**하므로
> 가끔 틀립니다. 정의가 고정된 계산이라면 코드로 옮기는 것이 맞습니다 —
> 그것이 `tool/` 모듈에서 만드는 MCP 도구입니다.
