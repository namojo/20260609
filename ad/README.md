# 광고 캠페인 주간 리포트 — 사례 실습 데이터

> 교육 사이트 **2차시(지식을 파일로)** 사례의 실제 입력 데이터입니다.
> 4차시(전문가 팀)·5차시(출력 계약)·6차시(Tool) 실습도 이 데이터로 진행합니다.
> 등장하는 회사·브랜드·수치는 모두 **가상**입니다.

## 1. 상황

광고대행사 AE **정하늘 대리**는 매주 월요일, 5개 매체에서 성과 파일을 받아
광고주 제출용 주간 리포트를 만듭니다. 매주 2시간 30분이 걸립니다.

양식은 매체가 정해 주는 대로 받는데, **컬럼명·지표 정의·통화 기준이 전부 다릅니다.**

## 2. 데이터 규모

| | |
|---|---|
| 파일 | **10개** (5개 매체 × 2주) |
| 행 | **252행** (일자 × 캠페인) |
| 기간 | 2026-07-06 ~ 07-12 (W2) · 07-13 ~ 07-19 (W3) |
| 캠페인 | 네이버 4 · 카카오 3 · 메타 4 · 구글 4 · 틱톡 3 = **18개** |

**손으로 하면**: 파일 10개를 열고 → 컬럼명을 맞추고 → 카카오는 VAT를 나누고 →
메타는 목적별로 전환을 걸러내고 → 날짜 3형식을 통일하고 → 캠페인 18개를 매체별로
집계하고 → 전주 대비를 계산합니다. 매주 2시간 30분이 걸리는 이유입니다.

**2주치가 들어 있는 이유**: 리포트에 **전주 대비 증감**이 필수 항목이라
지난주(W2) 데이터가 있어야 계산이 됩니다.

```
ad/
├── README.md                        ← 본 문서
├── data/                            ← 입력 (10개)
│   ├── 2026-07-W2_네이버GFA.csv      ├── 2026-07-W3_네이버GFA.csv
│   ├── 2026-07-W2_카카오모먼트.csv    ├── 2026-07-W3_카카오모먼트.csv
│   ├── 2026-07-W2_메타.csv           ├── 2026-07-W3_메타.csv
│   ├── 2026-07-W2_구글애즈.csv        ├── 2026-07-W3_구글애즈.csv
│   └── 2026-07-W2_틱톡.csv           └── 2026-07-W3_틱톡.csv
├── new/                             ← 나중에 추가된 매체 (2차시 7-5 용어 등록 실습)
│   └── 2026-07-W3_당근.csv
├── 매체_표준용어집.md                  ← 지식 베이스 (2차시 사례의 결과물)
└── prompt.md                        ← 에이전트 지시서
```

## 3. 매체별로 무엇이 다른가

| 매체 | 노출 컬럼 | 집행액 | 날짜 | 캠페인 |
|---|---|---|---|---|
| 네이버GFA | `노출수` | 광고비 **VAT별도** | `2026-07-13` | 4개 |
| 카카오모먼트 | `노출` | 소진금액 **VAT포함** | `26.7.13` | 3개 |
| 메타 | `Impressions` | `Amount spent (KRW)` | `2026-07-13` | 4개 (**목적 2종 혼재**) |
| 구글애즈 | `Impr.` | `Cost` | `2026/07/13` | 4개 |
| 틱톡 | `Imp` | `Spend` | `20260713` | 3개 (노출 600 대 테스트 포함) |

### 데이터에 심어 둔 함정 네 가지 (실측)

| 함정 | 용어집 없이 통합하면 |
|---|---|
| 카카오 **VAT 포함** | 카카오 ROAS **163.3% → 148.5%** — 성과를 실제보다 나쁘게 보고 |
| 메타 **`Results`** — `Link clicks` 목적 행의 값은 클릭수 | 메타 전환 **1,120 → 15,683건(14배)**, CPA **34,886 → 2,491원**. 전체 전환도 5,705 → 20,268건(3.6배) |
| 날짜 **3가지 형식** | 주차 집계가 어긋난다 |
| 틱톡 **`Lumiere_Spark_Test`** (노출 600대) | 전환 0인데 CTR 1.6% 로 효율이 좋아 보인다 |

### 정답 (용어집 적용 시)

| 지표 | W2 (지난주) | W3 (이번주) | 전주 대비 |
|---|---|---|---|
| 전환 | 6,944건 | 5,705건 | -17.8% |
| CPA | 21,345원 | 24,136원 | **+13.1%** |
| ROAS | 413.6% | **366.9%** | -46.7%p |
| 목표(350%) 달성률 | 118.2% | **104.8%** | 겨우 달성 |

> 위 숫자는 이 데이터로 직접 계산해 확인한 값입니다. 실습 결과와 대조해 보세요.
> 매체별로는 카카오모먼트(163%)가 목표에 크게 미달합니다 — 리포트의 핵심 이슈입니다.

## 4. 실습 방법

### 준비 — 이 폴더에서 Claude Code 실행

```powershell
cd C:\harness-edu\ad     # macOS: cd ~/harness-edu/ad
claude
```

### A. 용어집 없이 먼저 (2차시 실습 A)

입력창에:

```
data 폴더의 매체별 성과 파일을 하나로 통합해서 주간 리포트를 만들어줘.
```

**관찰 포인트**: `/clear` 후 두 번 돌려 보세요. 매체명 표기·전환 정의·VAT 처리가
회차마다 달라지고, 위 네 가지 함정 중 최소 두 개가 조용히 틀립니다.

### B. 용어집과 함께 (2차시 실습 B)

```
이 폴더의 prompt.md 를 읽고, 거기 적힌 절차대로 수행해줘.
```

**검수 체크리스트** — 위 &ldquo;정답&rdquo; 표와 대조하면 바로 보입니다.

- [ ] 전체 ROAS 가 **366.9%** 근처인가 (용어집 없이 하면 361% 대로 나온다)
- [ ] 전체 전환이 **5,705건** 근처인가 (2만 건대면 메타 Results 를 잘못 합산한 것)
- [ ] 카카오 집행액이 VAT 별도로 환산되었는가
- [ ] `Lumiere_Spark_Test` 가 **데이터 부족** 으로 표시되었는가
- [ ] 전주 대비 CPA **+13.1%** 가 리포트에 있는가
- [ ] 정규화 이력(어느 컬럼을 무엇으로 매핑했는지)이 보고되었는가

## 4-1. `new/` 폴더 — 용어 등록 실습용

`new/2026-07-W3_당근.csv` 는 **나중에 추가된 매체**를 가정한 파일입니다. 2차시 7-5절
(새 용어를 표준으로 등록하기)에서 씁니다.

| 항목 | 값 |
|---|---|
| 행 | 14행 (7일 × 캠페인 2개) |
| 컬럼 | `광고일자` `광고명` `노출` `유입` `유입률(%)` `광고비(VAT포함)` `노출당과금` `구매` `구매금액` |
| 날짜 형식 | `2026.07.13` — **네 번째 형식** |
| VAT | **포함** (÷ 1.1 필요) |
| 함정 | `노출당과금` 은 **우리 표준에 없는 개념** — 매핑하지 말고 `[확인 필요]` 로 남겨야 함 |

> **`data/` 에 넣지 않은 이유**: 위 "정답" 표의 숫자가 달라지면 다른 차시의 대조가 전부 깨집니다.
> 이 파일은 **등록 절차만** 연습하는 용도이며, 통합 집계에는 넣지 않습니다.
> 참고로 이 매체만 따로 계산하면 ROAS 193.9% (VAT 별도 환산 기준)입니다.

## 5. 뒤 차시와의 연결

| 차시 | 이 데이터로 하는 것 |
|---|---|
| **2차시** | 용어집(Skill)을 파일로 꺼내면 결과가 안정되는 것을 확인<br>+ 스킬로 승격하고, `new/` 의 새 매체를 **표준으로 등록**하는 절차 실습 |
| **4차시** | 이 업무의 에이전트 팀 구성 — `my-harness/input/` 에 이 데이터를 넣고 팀을 만든다 |
| **5차시** | 리포트 항목을 **출력 계약**으로 고정 |
| **6차시** | CPA·ROAS 재계산을 **Tool** 로 옮기기 |

> 6차시 포인트: 위 재계산 규칙을 용어집(설명서)에 적어 두어도 모델은 **암산**하므로
> 252행을 다룰 때 가끔 틀립니다. 정의가 고정된 계산이라면 코드로 옮기는 것이 맞습니다.
