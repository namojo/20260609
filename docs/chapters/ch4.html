모르는 분야의 전문 문서를 써야 한다면? 같은 입력으로 혼자 쓴 것과 전문가 팀이 쓴 것을 나란히 놓고, 차이가 어디서 왔는지 찾습니다. 그리고 내 업무의 팀을 직접 만듭니다.

macOS · 터미널

이 차시에서 처음 나오는 말

에이전트 정의
담당자 한 명의 역할·경계·금지사항을 적어 둔 파일. .claude/agents/ 안에 한 명당 한 장씩 들어갑니다.
중간 산출물
최종 결과물이 아니라 그 앞 단계에서 만들어지는 자료. 이 차시의 핵심 — 품질 차이는 여기서 갈립니다.
검증자 분리
만든 사람이 자기 결과를 승인하지 않고, 별도 담당이 대조 검사하는 구조.
팀 아키텍처 패턴
팀을 짜는 정해진 모양 6가지. 순서대로 넘기기, 나눠서 동시에 하기 등.

이 차시에서 배우는 것

  • 단일 프롬프트와 전문가 팀의 차이를 결과물 네 지점에서 직접 확인한다
  • 그 차이가 중간 산출물에서 왔다는 것을 파일로 확인한다
  • 내 업무의 전문가 팀을 직접 만들어 파일로 남긴다

1. 실험 조건 — 모르는 분야의 문서를 써야 한다면

입력은 나라장터에 실제로 올라온 과업지시서 1건입니다. 국가통합바이오빅데이터 사업의 병원 진료기록 연계 구축 건이고, 문서에는 이런 단어들이 이름만 나옵니다.

과업지시서에 등장하는 용어
FHIR · KCD-8 · 심평원 EDI · 가명화 · ETL

보건의료 데이터를 모르는 사람이 이 문서로 제안서를 써야 합니다. 이것이 실험 조건입니다. 여러분도 업무에서 비슷한 상황을 겪습니다 — 낯선 부서의 요청, 처음 보는 규격, 이름만 아는 제도.

트랙 A트랙 B
방식단일 프롬프트 한 번전문가 에이전트 팀
지시"과업지시서로 제안서를 작성해줘"5명이 순서·병렬로 분업 + 검증
결과제안서A_단일패스.docx (3쪽)제안서B_하네스.docx (8쪽)
🔎

공정한 비교입니다. A는 일부러 못 쓴 것이 아닙니다. 구조가 잡혀 있고 문장도 매끄러운 단일 패스의 "괜찮은 평균" 입니다. 기준선이 정직해야 비교가 의미를 가집니다. 그리고 쪽수가 많아서 좋은 것도 아닙니다 — 무엇이 늘었는지가 중요합니다.

2. 결과 비교 — 차이가 남는 네 지점

두 결과물은 이미 저장소에 들어 있습니다. 직접 열어 비교합니다.

Windows · PowerShell
cd C:\harness-edu\harness; claude
macOS · 터미널
cd ~/harness-edu/harness && claude
Claude Code 입력창에 붙여넣기
제안서A_단일패스.docx 와 제안서B_하네스.docx 를 둘 다 읽고,
아래 네 항목에서 무엇이 다른지 표로 비교해줘. 쪽수 말고 내용으로 비교해줘.

1. 배경지식 (모르는 분야를 어떻게 다뤘나)
2. 요구사항 대응 (빠뜨린 것이 있나)
3. 계약 조건 조항 대응
4. 검증 가능성 (숫자로 확인 가능한 약속이 있나)
👀

예상 결과: 아래와 비슷한 비교표가 나옵니다. AI가 만든 표를 직접 문서를 열어 확인해 보세요 — 이것도 검수 연습입니다.

비교 지점A · 단일 패스B · 하네스
배경지식"표준코드에 맞추어 매핑합니다" — 과업지시서 단어를 되풀이6종 코드체계별 매핑 전략 표 (KR Core ValueSet, KCD 전환표, 원내-EDI 매핑 등)
전수 대응눈에 띄는 요구 위주. 보안 연계망·가명화 취급이 얕음REQ-01~11 추적 매트릭스, 검수 기준표
조건 조항사실상 언급 없음CON-01~07 전건 수용 확약표 (SLA, 라이선스, 상주 인원 등)
검증 가능성"약 3주", "품질을 확보"W1~W9 일정 + 임계경로, 미매핑률 ≤1%, 가명화 누출 0건

한 줄 요약 — A는 과업지시서를 요약한 제안서, B는 과업지시서에 응답한 제안서.

2-2. 차이의 근원은 문장이 아니라 파일 하나

B의 모든 우위는 어디서 왔을까요? 더 좋은 문장을 써서가 아닙니다. 중간에 만든 파일 하나에서 나왔습니다. 직접 열어 봅니다.

Claude Code 입력창에 붙여넣기
artifacts/요구사항_인벤토리.md 를 읽고,
이 파일이 무엇을 정리한 것인지, 항목이 몇 개인지 알려줘.
그리고 이 파일이 없었다면 제안서에서 무엇이 빠졌을지 설명해줘.
👀

예상 결과: 과업지시서에서 뽑아낸 요구사항이 ID를 달고 전수 정리되어 있습니다.

인벤토리의 구조
REQ-01 ~ REQ-11   기능 요구사항 11건
DOM-01 ~ DOM-13   도메인 지식 항목 13건
CON-01 ~ CON-07   계약 조건 7건
DEL-01 ~ DEL-04   산출물 4건

이 지루한 작업 — 전부 뽑아서 번호를 붙이는 일 — 하나가 뒤의 모든 것을 만들어 냅니다.

인벤토리가 낳은 것어떻게
추적 매트릭스REQ 번호별로 "제안서 어디에서 답했는지" 표시
조건 확약표CON 번호를 하나씩 훑으며 수용 여부 명시
검수 기준표DEL 번호별 인수 조건 정의
누락 없음의 근거검증자가 ID를 하나씩 대조할 수 있음
🔎

이 차시의 핵심 문장: 하네스란 "중간 산출물을 만드는 일을 역할로 강제하는 장치" 입니다. 사람도 똑같습니다 — 급하면 요구사항 정리를 건너뛰고 바로 본문을 씁니다. 팀에 "그것만 하는 담당" 이 있으면 건너뛸 수 없습니다.

2-3. 검증자 분리 — 잘 쓰는 것과 빠뜨리지 않는 것은 다른 능력

조건 조항 7건이 A에서 빠진 이유는 더 노력하지 않아서가 아닙니다. 글을 쓰는 사람의 시선으로는 계약 조건이 눈에 잘 안 들어옵니다.

혼자 쓰고 혼자 검토

"다 썼나?" 를 자기 기억으로 확인합니다. 자기가 못 본 것은 검토할 때도 안 보입니다.

검증 담당을 따로 둠

"인벤토리 ID를 하나씩 원고에서 찾아라" 라는 기계적 대조가 임무입니다. 없으면 담당자를 지목해 수정시킵니다.

하네스 4원리 중 네 번째 — 검증자는 분리한다
만든 주체가 자기 결과를 최종 승인하지 않습니다. 여러분이 만들 모든 팀에 검증 담당 한 명을 반드시 넣으세요.

2-4. A가 이기는 경우도 압니다

내부 검토용 초안, 참고용 요약이라면 A의 속도가 정답입니다. 하네스는 "조항 하나를 빠뜨리면 탈락하는" 고부담 문서에서 정당화됩니다. 3차시에서 배운 "이 일은 몇 단계짜리인가" 판단이 여기서 다시 쓰입니다.

3. 하네스의 구성물 열어 보기

트랙 B를 가능하게 한 파일들이 harness/ 폴더에 그대로 들어 있습니다. 무엇이 들어 있는지 봅니다.

Claude Code 입력창에 붙여넣기
이 폴더의 CLAUDE.md 와 .claude/agents/, .claude/skills/ 를 훑어보고,
각 파일이 무슨 역할인지 한 줄씩 정리해줘.
구성물무엇인가이 과정의 개념
CLAUDE.md이 프로젝트에서 항상 지켜야 할 규칙팀 공통 규범
.claude/agents/ 5개담당자별 역할·경계 정의Agent (누가)
.claude/skills/ 3개방법론·도메인 지식·문서 표준Skill (무엇을·어떻게)

3-1. 담당자 다섯 명은 각각 무엇을 하나

순서담당맡은 일단일 프롬프트에는 없던 것
1요구분석가
rfp-analyst		요구사항 전수 추출 · ID 부여목적 문단에 숨어 있던 요구, 표 각주의 강행 규정까지 승격
2도메인 전문가
domain-expert		분야 지식 주입문서 밖 지식 — 코드 전환표, 관련 법 조항
3기술 설계
solution-architect		해결 방안 설계둘이 동시에 진행 (서로 기다리지 않음)
3관리 담당

4검증자
compliance-reviewer		전건 대조 검사인벤토리 ID 전건을 원고에서 확인, 통과할 때까지 수정 루프

3-2. 2차시에서 만든 용어집이 여기서 "스킬"이 됩니다

도메인 전문가가 똑똑해서 코드 전환표를 아는 게 아닙니다. medical-data-standards 스킬 파일에 사전이 들어 있어서 가능합니다. 그리고 그 사전은 다음 의료 사업에서 그대로 재사용됩니다.

2차시: 용어집을 파일로 → 결과가 안정됨
4차시: 그 파일을 특정 담당자에게 쥐여 줌 → 그 담당자가 전문가가 됨
이것이 Skill과 Agent의 결합입니다.

3-3. 팀을 짜는 여섯 가지 모양 (이름만 알아 두기)

팀 구조에는 정해진 패턴이 있습니다. 외울 필요는 없습니다 — 하네스 플러그인이 일에 맞는 모양을 골라 줍니다. 다만 결과물을 볼 때 "아, 이 모양이구나" 알아보면 좋습니다.

패턴모양어울리는 일
파이프라인순서대로 넘긴다앞 단계 결과가 있어야 다음이 되는 일 (이번 실습)
팬아웃 · 팬인나눠서 동시에 → 합친다서로 독립된 조사·분석
전문가 풀상황 따라 골라 부른다매번 필요한 전문가가 다른 일
생성 · 검증만들고 → 검사한다품질이 중요한 산출물
관리자형한 명이 배분·조율일이 유동적으로 늘어나는 경우
위임형위에서 아래로 쪼개 내린다큰 과제를 계층으로 분해

4. 사례 — 광고 AE의 전문가 팀

1차시부터 따라온 정하늘 대리가 자기 업무의 하네스를 만든 과정입니다. 프롬프트와 결과, 그리고 무엇을 고쳤는지까지 그대로 봅니다.

사례 정하늘 대리의 하네스 4차시 결과물 · 루미에르 주간 리포트 팀

① 내 업무를 한 문단으로 — 1차시 업무 카드를 그대로 옮김

넣을 것정하늘 대리의 답
도메인광고대행사 AE의 디지털 캠페인 주간 성과 보고 (화장품 브랜드, 5개 매체 운영)
입력5개 매체 성과 파일(엑셀·CSV) + 지난주 리포트 + 캠페인 목표(월 ROAS 350%)
산출물광고주 제출용 주간 요약 1장 + 이슈·다음 행동 목록
품질 기준숫자는 원본과 100% 일치 · 매체별 용어 통일 · 이슈가 하나도 빠지지 않을 것 · 지난주 대비 증감 필수

② 실제로 넣은 프롬프트

정하늘 대리가 Claude Code에 넣은 것
하네스 구성해줘.

도메인: 광고대행사 AE의 디지털 캠페인 주간 성과 보고.
      화장품 브랜드 1개, 5개 매체(네이버GFA·카카오모먼트·메타·구글애즈·틱톡) 운영.
입력: 매체별 성과 파일(엑셀/CSV) 5개, 지난주 리포트, 캠페인 목표(월 ROAS 350%)
산출물: 광고주 제출용 주간 요약 1장 + 이슈·다음 행동 목록
품질 기준: 숫자는 원본과 100% 일치, 매체별 용어는 사내 표준으로 통일,
         이슈는 하나도 빠지면 안 됨, 지난주 대비 증감이 반드시 포함될 것

에이전트는 3~5명으로 하고, 결과를 대조 검증하는 담당을 반드시 포함해줘.

③ 만들어진 팀 — 4명 + 검증자

#담당자맡은 일검증 담당
1데이터 정규화 담당
data-normalizer		5개 매체 파일을 읽어 용어집 기준으로 통일. VAT 별도 환산, 매체별 컬럼 매핑—
2성과 분석 담당
performance-analyst		CPA·ROAS·달성률 계산, 지난주 대비 증감 산출, 이상 지표 탐지—
3이슈·액션 담당
issue-planner		지표 이상의 원인 후보를 정리하고 다음 주 실행안 제안 (예산 재배분·소재 교체)—
4리포트 작성 담당
report-writer		광고주 톤에 맞춰 1장으로 집필—
5수치 검증 담당
qa-checker		원본 파일과 리포트 숫자를 항목별 대조, 이슈 목록 누락 확인✔

④ 점검에서 걸러낸 두 가지

처음 생성 결과에서 고친 것
  • 담당자가 7명이었습니다. "매체별 담당"이 5명으로 쪼개져 있었습니다 → "데이터 정규화 담당 1명"으로 합쳐 달라고 요청. 매체가 달라도 하는 일이 같으니 나눌 이유가 없습니다.
  • 검증 담당이 "리포트 작성 담당"에 흡수돼 있었습니다. 작성자가 자기 숫자를 검토하는 구조였습니다 → 별도 담당으로 분리. 4차시의 핵심 원리입니다.
고칠 때 넣은 프롬프트
매체별로 나뉜 담당 5명을 "데이터 정규화 담당" 1명으로 합쳐줘.
매체가 달라도 하는 일(용어 통일·VAT 환산·컬럼 매핑)이 같아.

그리고 수치 검증을 리포트 작성 담당이 겸하지 않게 분리해줘.
검증 담당은 원본 파일과 리포트를 항목별로 대조하고,
불일치나 누락을 찾으면 해당 담당자를 지목해 수정 요청하도록 정의해줘.

4-1. 직접 해보기 — 준비된 데이터로

사례를 읽는 것만으로는 감이 안 옵니다. 정하늘 대리와 같은 데이터로 직접 팀을 만들어 보세요. 실습 저장소에 ad/ 폴더로 준비되어 있습니다.

5. 스스로 점검

  • A와 B의 차이를 중간 산출물이라는 말로 설명할 수 있다
  • "잘 쓰는 것과 빠뜨리지 않는 것은 다른 능력" 의 뜻을 안다
  • 하네스가 정당화되지 않는 경우도 말할 수 있다
  • 내 도메인 에이전트가 생성되었고 역할을 한 줄씩 말할 수 있다
  • 팀에 검증 담당이 포함되어 있다
  • 생성된 파일이 어디 있는지 안다

6. 더 해보기 (선택)

  • 평가위원 롤플레이 — 새 대화에서 AI에게 조달 평가위원 역할을 주고 A·B를 4개 항목으로 채점시켜 보세요. 점수 차가 어느 항목에서 벌어지는지 보면 하네스의 효과 지점이 분명해집니다.
