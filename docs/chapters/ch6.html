계산은 도구에게 — 나만의 Tool 붙이기

AI는 "그럴듯하게" 계산합니다. 검증할 수 없는 숫자는 보고서에 못 씁니다. 계산을 코드에 위임하고, AI에게는 해석만 맡깁니다.

6 / 7 🧑‍💼 실무 사례 🐍 Python (읽기만)

이 차시에서 준비할 것

선행5차시 · 반복을 시스템으로 완료
필수 설치MCP 서버 설치가이드 (20~30분)
실습 파일tool/mcp-server/
가져올 것내 업무에서 계산하는 일 목록
🐍

코드를 쓰지 않습니다. 이미 만들어진 파이썬 파일을 읽고 연결만 합니다. 목표는 "함수 하나에 표시 한 줄 붙이면 도구가 된다" 는 감각까지입니다. 설치가 아직이면 설치가이드를 먼저 하세요.

이 차시에서 처음 나오는 말

도구 (Tool)
AI가 실제로 실행하는 코드. 설명서를 읽고 해석하는 것이 아니라 계산 결과를 그대로 받습니다.
MCP
도구를 AI에 붙이는 공개 표준 규격. 하나 만들면 Claude Code·Codex 등 여러 AI가 같이 씁니다.
결정론
같은 입력이면 언제나 같은 출력. 코드의 성질이고, 모델에는 없는 성질입니다.
OEE
설비종합효율. 가동률 × 성능 × 품질로 계산하는 정의가 고정된 제조 지표입니다.

이 차시에서 배우는 것

  • 같은 질문에 암산한 답과 도구가 계산한 답을 비교한다
  • Skill(설명서)과 Tool(계산기)을 구분해서 쓸 수 있다
  • 내 업무에서 도구로 만들 계산 세 가지를 찾아낸다

1. 문제 체험 — 그럴듯한 숫자의 위험

"B라인 어제 OEE 알려줘" 라는 질문을 도구 없이 던져 봅니다.

Windows · PowerShell
cd C:\harness-edu\tool\mcp-server; claude
macOS · 터미널
cd ~/harness-edu/tool/mcp-server && claude
Claude Code 입력창에 붙여넣기 — 1회차
data/production.csv 를 보고 B라인 2026-07-14 의 OEE를 알려줘.
OEE는 가동률 × 성능 × 품질이야. 계산 과정도 보여줘.

대화를 비우고 똑같이 한 번 더 물어봅니다.

Claude Code 입력창 — 비우기
/clear
🔎

관찰 포인트 — 두 답의 소수점 아래를 비교하세요. 반올림 지점, 중간 계산 방식, 최종 값이 미묘하게 다를 수 있습니다. 그리고 더 중요한 것:

이 숫자가 맞는지 어떻게 확인하죠? 계산 과정을 사람이 다시 검산해야 한다면, AI를 쓴 이득이 사라집니다.

도구 없이 — AI가 암산

가동률 0.75쯤, 성능 0.94쯤...
OEE 대략 70% 안팎으로 보입니다

  • 그럴듯하지만 검증 불가능
  • 같은 질문에 매번 미묘하게 다름
  • 보고서에 쓸 수 없음

도구 있이 — 코드가 계산

{ availability: 0.75, performance: 0.9444,
quality: 0.9853, oee_pct: "69.8%",
bottleneck: "가동률" }

  • 몇 번을 돌려도 69.8%
  • 병목이 가동률이라는 진단까지
  • 근거가 코드에 남아 있음

2. 개념 — Skill은 설명서, Tool은 계산기

2-1. 세 축이 여기서 완성됩니다

축무엇인가형태같은 질문에 같은 답?배운 차시
Agent역할·경계 (누가)지시문 파일—4차시
Skill지식·절차 (무엇을·어떻게)AI가 읽는 문서✗ 모델이 해석2차시
Tool실행 수단 (무엇으로)실제 코드✓ 항상 같음이번 차시

판단 규칙 하나만 기억하세요
정의가 고정돼 있고 늘 같은 답이 나와야 하는 일 (계산 · 조회 · 외부 시스템 호출) → Tool
맥락에 따라 달라지는 판단 (무엇이 중요한가 · 어떻게 쓸까 · 어떤 톤으로) → Skill

2차시에서 만든 용어집에 "OEE는 가동률 × 성능 × 품질" 이라고 적어 두기만 하면 모델이 그 설명을 읽고 직접 암산합니다. 숫자가 커지면 자주 틀립니다. Tool은 그 계산을 코드로 실행합니다.

2-2. 왜 표준을 쓰나 — 한 번 만들어 여러 곳에서

이 도구는 MCP 라는 공개 표준으로 만들어져 있습니다. 그래서 서버 하나를 만들어 두면:

  • Claude Code 가 호출할 수 있고,
  • Codex 도 호출할 수 있고,
  • 앞으로 나올 다른 AI도 그대로 씁니다.

"우리 팀 계산기"를 도구마다 다시 만들 필요가 없다는 뜻입니다. 이것이 사내 도구를 자산으로 만드는 방법입니다.

2-3. 좋은 도구는 값만 주지 않습니다

이 실습의 compute_oee 는 OEE 숫자만 돌려주지 않고 병목이 어느 축인지(bottleneck)까지 계산해 줍니다. 도구가 한 걸음 더 계산해 주면, 모델은 그만큼 더 나은 해석을 얹을 수 있습니다.

3. 도구 붙이고 확인하기

설치가이드를 이미 마쳤다면 등록은 끝나 있습니다. 확인부터 합니다.

등록은 됐는데 이 폴더에서만 보인다면 기본값인 local 스코프로 등록된 것입니다. claude mcp remove production-metrics 후 --scope user 를 붙여 다시 등록하세요 — 7차시에서 my-harness 폴더로 옮기면 도구가 사라집니다.

Claude Code를 실행하고 입력창에서 연결 상태를 봅니다.

예상 결과: 화면에 도구 호출 표시가 뜨고(승인을 물으면 승인), 69.8% 라는 값이 나옵니다. 1절의 암산 값과 비교해 보세요.

Claude Code 입력창에 붙여넣기 ② — 도구 + 해석
production-metrics 도구로 2026-07-14 A·B·C 세 라인의 OEE를 구하고,
가장 낮은 라인의 병목이 무엇인지, 개선하려면 어디를 봐야 하는지 정리해줘.
🔎

관찰 포인트: AI가 도구를 세 번 호출해 정확한 값을 받아 온 뒤, 거기에 해석만 얹습니다. "정확한 산수는 도구, 해석은 모델" 이라는 분업이 눈으로 보입니다.

⚠️

AI가 도구를 안 부르고 직접 암산하려 하면: "compute_oee 도구를 사용해서" 라고 명시하세요. 도구 설명이 구체적일수록 자동 호출이 잘 됩니다 — 도구 설명문도 지시서입니다.

4-2. 코드를 열어 보기 (읽기만 합니다)

이 도구가 어떻게 생겼는지 확인합니다. 고칠 필요 없습니다.

Claude Code 입력창에 붙여넣기
server.py 를 열어서, 코드를 모르는 사람도 이해할 수 있게
"함수 하나가 어떻게 도구가 되는지" 설명해줘. 세 가지만 짚어줘.
핵심은 이게 전부입니다
@mcp.tool()                                  ← 이 한 줄이 "이건 도구다" 표시
def compute_oee(line: str, date: str) -> dict:
    """지정한 라인·날짜의 OEE를 계산한다."""   ← 이 설명을 모델이 읽고 언제 쓸지 판단
    ...
    return { "oee_pct": "69.8%", ... }        ← 돌려준 값이 그대로 모델에게 전달
세 가지만 기억뜻
표시 한 줄@mcp.tool() 을 붙인 함수 하나가 곧 도구 하나
설명문모델은 이 문장을 읽고 언제 이 도구를 부를지 판단합니다. 2차시의 "좋은 설명서" 원리와 같습니다
입력·출력필요한 값(라인·날짜)과 돌려줄 값이 정해져 있습니다 — 5차시의 계약과 같은 개념

Tool은 특별한 기술이 아닙니다. 팀이 평소 엑셀·매크로로 하던 계산을 함수로 옮기고 표시 한 줄을 붙이면, 그 순간 모든 AI가 쓸 수 있는 사내 도구가 됩니다.

4-3. (선택) 같은 도구를 Codex에도

Codex 를 설치했다면 코드를 한 줄도 바꾸지 않고 같은 도구를 붙일 수 있습니다. 방법은 설치가이드 5-2절에 있습니다.

🔎

관찰 포인트: 2차시의 스킬(문서)은 도구마다 복사해야 했지만, Tool은 하나의 서버를 양쪽이 각자 등록해 공유합니다. 계산 로직의 원본이 한 곳뿐이라 고칠 때도 한 번만 고칩니다.

5. 사례 — 광고 AE의 Tool 후보

사례 정하늘 대리의 Tool 후보 6차시 결과물

이 사례의 계산 대상 데이터는 저장소 ad/ 폴더에 있습니다. VAT 처리·전환 판정이 섞인 실제 값이라, 암산과 도구의 차이를 여기서도 확인할 수 있습니다.

① Skill과 Tool 구분 — 광고 업무로 연습

하는 일구분왜
ROAS = 전환매출 ÷ VAT별도 집행액 계산Tool정의가 고정. 늘 같은 값이 나와야 함
이번 주 리포트를 광고주 톤으로 다듬기Skill상대와 맥락에 따라 달라지는 판단
매체별 예산 소진율과 잔여일 대비 페이스 계산Tool날짜 계산 + 나눗셈. 사람이 하면 실수함
어떤 소재를 먼저 교체할지 결정Skill브랜드 톤·시즌·광고주 취향이 섞인 판단
메타 "결과" 컬럼이 전환인지 판별Skill캠페인 목적을 읽고 해석해야 함 (2차시 용어집이 담당)
2차시 용어집에서 하나가 승격됐습니다

2차시에 정하늘 대리는 "ROAS는 매체 값을 쓰지 말고 재계산한다" 를 용어집(Skill)에 적었습니다. 그런데 이건 설명서에 적을 게 아니라 코드가 할 일이었습니다.

실제로 용어집만 있던 3주 동안, AI가 VAT 환산을 한 번 빠뜨렸습니다. 설명서를 읽고 암산했기 때문입니다.

② Tool 후보 3개

#계산 이름입력출력
1성과 지표 재계산매체, 집행액(VAT 포함/별도 구분), 전환수, 전환매출CPA, ROAS, CTR, CVR — 전부 VAT 별도 기준
2예산 소진 페이스월 예산, 현재까지 집행액, 오늘 날짜, 캠페인 종료일소진율(%), 일 평균 집행액, 남은 일수 대비 초과/미달 금액
3CPA 변동 원인 분해이번 주·지난 주의 노출·클릭·전환·집행액CPA 증감률 + 원인이 CTR 하락인지 CVR 하락인지 단가 상승인지

③ 한 걸음 더 — 값 말고 진단까지

3번 도구가 그 예입니다. CPA가 올랐다는 숫자만으로는 아무것도 못 합니다. 왜 올랐는지가 있어야 다음 행동이 나옵니다.

3번 도구가 돌려주는 형태 (설계안)
{ "cpa_prev": 12400, "cpa_now": 15800, "change_pct": "+27.4%",
  "driver": "CTR 하락",
  "detail": "노출 +8% / 클릭 -19% / 전환율은 유지 → 소재 피로도 의심",
  "suggested_action": "상위 3개 소재 교체 검토" }
이 한 줄이 리포트를 바꿉니다

예전 리포트: "CPA가 27% 상승했습니다. 모니터링하겠습니다."
지금 리포트: "CPA 27% 상승, 원인은 CTR 하락(소재 피로도). 상위 3개 소재 교체를 제안합니다."

5차시에서 "다음 행동"을 필수 항목으로 만들었는데, 이 도구가 있어야 그 칸을 제대로 채울 수 있습니다.

④ 지금 방식 vs 도구가 됐을 때

지금 방식엑셀에 매체별 시트를 만들어 두고 수식으로 계산. 매체가 추가되면 시트를 복사해 수식 참조를 손으로 고침
걸리는 시간 (1회)약 25분 (VAT 구분·수식 확인 포함)
틀렸던 적이 있는가있음. 후배가 카카오 VAT 처리를 놓쳐 그 매체 ROAS가 310% 대신 282% 로 보고됨. 광고주 미팅에서 정정
도구가 되면 달라지는 점매체가 늘어도 입력만 추가. VAT 처리를 사람이 기억할 필요가 없음. 몇 번을 돌려도 같은 값
만들어 줄 사람사내 데이터팀 (요청 시 이 표를 그대로 전달)
📌

이 표가 사내 도구 요청서입니다. "뭔가 자동화해 주세요" 보다 입력·출력·현재 방식·틀렸던 사례가 적힌 요청이 훨씬 빨리 만들어집니다. 실제로 정하늘 대리는 이 표로 데이터팀에 1번 도구를 요청했고, 반나절 만에 받았습니다.

6. 스스로 점검

  • 암산 답과 도구 답의 차이를 직접 봤다
  • /mcp 에서 도구가 connected 인 것을 확인했다
  • Skill과 Tool을 "늘 같은 답이 나와야 하는가" 로 구분할 수 있다
  • 도구가 값 + 진단을 함께 주면 좋은 이유를 안다
  • 내 업무의 Tool 후보 3개를 입력·출력까지 적었다

7. 더 해보기 (선택)

  • 도구 추가해 보기 — 날짜별 추이를 돌려주는 도구를 하나 더 붙여 달라고 요청해 보세요. 함수 하나를 추가하는 일입니다.
  • 이미 있는 도구 찾기 — 세상에는 공개된 MCP 서버가 많습니다. "만들기 전에 이미 있는지 찾는다" 도 중요한 감각입니다.
  • 원본 교안 — tool/README.md 에 심화 과제(원격 서버, 다른 도메인 확장)가 있습니다.
