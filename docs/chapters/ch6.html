이 차시에서 처음 나오는 말

환각 (할루시네이션)
AI가 사실이 아닌 것을 사실처럼 말하는 것. 모른다고 하지 않고 그럴듯하게 만들어 냅니다.
도구 (Tool)
AI가 실제로 실행하는 코드. 계산하거나, 외부에서 자료를 가져옵니다.
MCP
도구를 AI에 붙이는 공개 표준. 하나 만들면 Claude Code·Codex 등이 같이 씁니다.
결정론
같은 입력이면 언제나 같은 출력. 코드의 성질이고, 모델에는 없는 성질입니다.

이 차시에서 배우는 것

  • 환각이 어떻게 생기고 왜 안 걸리는지 두 종류로 확인한다 — 계산과 사실
  • 도구를 붙여 지어내지 못하게 막는다 (계산 도구 · 법령 조회 도구)
  • 내 업무에 필요한 도구를 AI에게 시켜 직접 만든다

1. 문제 — 두 종류의 환각

1-1. 계산 환각 — 그럴듯한 숫자

Windows · PowerShell
cd C:\harness-edu\tool\mcp-server; claude
macOS · 터미널
cd ~/harness-edu/tool/mcp-server && claude
Claude Code 입력창에 붙여넣기
data/production.csv 를 보고 B라인 2026-07-14 의 OEE를 알려줘.
OEE는 가동률 × 성능 × 품질이야. 계산 과정도 보여줘.
🔎

관찰: 답은 그럴듯합니다. 그런데 이 숫자가 맞는지 어떻게 확인하죠? 계산 과정을 사람이 다시 검산해야 한다면 AI를 쓴 이득이 사라집니다. 소수점 아래가 회차마다 미묘하게 다르기도 합니다.

1-2. 사실 환각 — 있지도 않은 조문

더 위험한 쪽입니다. 숫자는 이상하면 눈에 띄지만, 법 조문·규정·인용은 틀려도 그럴듯합니다.

Claude Code 입력창에 붙여넣기
근로기준법에서 임산부의 야간·휴일 근로 제한을 정한 조문이 몇 조인지 알려주고,
그 조문 원문을 그대로 인용해줘. 몇 항까지 있는지도 알려줘.
⚠️

관찰: 조문 번호와 그럴듯한 문장이 나옵니다. 맞을 수도 있고 틀릴 수도 있습니다. 문제는 — 읽는 사람이 구분할 수 없다는 것입니다. 조문 번호가 하나 어긋나거나, 개정 전 내용이거나, 아예 없는 항이 섞여 있어도 문장은 매끄럽습니다.

보고서에 이대로 들어가면 어떻게 될까요. 이것이 사실 환각이 계산 환각보다 위험한 이유입니다.

두 환각의 공통점 — AI가 모른다고 말하지 않는다는 것입니다. 해결책도 같습니다. 지어낼 여지를 없애고 사실을 가져오는 창구를 붙입니다. 그 창구가 Tool 이고, 붙이는 표준이 MCP 입니다.

2. 개념 — Skill은 설명서, Tool은 창구

4. 실습 B — 법령 조회 도구 붙이기 (korean-law-mcp)

계산은 막았습니다. 이번엔 사실 차례입니다. 법제처 국가법령정보센터의 공식 데이터를 AI가 직접 조회하게 붙입니다.

💡

법률 담당이 아니어도 해볼 가치가 있습니다. "AI가 기억으로 답하던 것을 원문 조회로 바꾼다" 는 구조는 사내 규정·제품 사양·계약 조건 등 모든 ‘틀리면 안 되는 사실’ 에 똑같이 적용됩니다.

5. 실습 C — 도구 직접 만들기

마지막입니다. 없는 도구는 만들면 됩니다. 코드는 AI가 씁니다 — 우리는 무엇을 만들지 정합니다.

5-1. 먼저 구조만 봅니다

Claude Code 입력창에 붙여넣기 (tool/mcp-server 폴더에서)
server.py 를 열어서, 코드를 모르는 사람도 이해할 수 있게
"함수 하나가 어떻게 도구가 되는지" 세 가지만 짚어줘.
핵심은 이게 전부입니다
@mcp.tool()                                  ← 이 한 줄이 "이건 도구다" 표시
def compute_oee(line: str, date: str) -> dict:
    """지정한 라인·날짜의 OEE를 계산한다."""   ← 이 설명을 모델이 읽고 언제 쓸지 판단
    ...
    return { "oee_pct": "69.8%", ... }        ← 돌려준 값이 그대로 모델에게 전달
세 가지뜻
표시 한 줄@mcp.tool() 을 붙인 함수 하나 = 도구 하나
설명문모델은 이 문장을 읽고 언제 부를지 판단합니다 — 2차시의 "좋은 설명서" 원리와 같습니다
입력·출력필요한 값과 돌려줄 값이 정해져 있습니다 — 이것이 계약입니다

5-2. 도구 하나 추가하기

지금 도구 3개로는 답할 수 없는 질문이 있습니다 — "이번 주 B라인 OEE가 오르는 추세인가?" 날짜별 추이를 돌려주는 도구를 추가합니다.

Claude Code 입력창에 붙여넣기
server.py 에 weekly_trend 도구를 추가해줘.

- 입력: line (라인 이름)
- 하는 일: 그 라인의 날짜별 OEE를 계산해서 시간순으로 돌려준다
- 출력: 날짜별 OEE 목록 + 첫날 대비 마지막날 증감 + 추세(상승/하락/보합)
- 값만 주지 말고 어느 축(가동률·성능·품질)이 추세를 이끌었는지도 함께

기존 도구 3개는 건드리지 말고, 설명문(docstring)은 모델이 언제 부를지
판단할 수 있게 구체적으로 써줘.
👀

예상 결과: server.py 에 함수가 하나 늘어납니다. 승인을 물으면 내용을 보고 승인하세요. 코드를 이해하지 못해도 됩니다 — 다음 단계에서 실제로 도는지로 확인합니다.

6. 정리 — 언제 도구로 만드나

이런 일Skill / Tool왜
정해진 공식으로 계산Tool늘 같은 답이 나와야 함
법령·규정 원문 인용Tool기억이 아니라 원본에서 가져와야 함
사내 시스템 조회Tool실제 데이터가 필요함
보고서 톤 다듬기Skill맥락에 따라 달라지는 판단
무엇을 먼저 보고할지Skill사람의 우선순위가 들어감

Tool은 특별한 기술이 아닙니다. 팀이 엑셀·매크로로 하던 계산, 매번 사이트에서 찾아보던 조회 — 그것을 함수로 옮기고 표시 한 줄을 붙이면 사내 도구가 됩니다. 그리고 그 코드는 AI가 씁니다. 실무자가 할 일은 무엇이 틀리면 안 되는지 아는 것입니다.

7. 스스로 점검

  • 계산 환각과 사실 환각을 각각 직접 봤다
  • 왜 사실 환각이 더 위험한지 설명할 수 있다
  • /mcp 에서 도구가 connected 인 것을 확인했다
  • (선택) 법령 도구로 존재하지 않는 조문을 잡아냈다
  • 도구를 하나 추가하고 이름을 말하지 않아도 호출되는 것을 봤다
  • 내 업무에서 Tool로 만들 것을 하나 이상 떠올렸다
