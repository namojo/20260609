이 차시에서 배우는 것

  • 반복 실행에서 형식이 흔들리는 문제를 직접 겪는다
  • 항목·허용 값을 미리 정하는 출력 계약으로 그 흔들림을 없앤다
  • 자동 실행 전에 권한을 어디까지 줄지 정하는 기준을 갖는다

1. 문제 — 매주 조금씩 달라집니다

금융회사 준법·리스크팀의 월요일 루틴입니다.

  1. 금융위·금감원·주요 매체에서 지난 주 규제·공시 뉴스를 훑는다
  2. 우리 조직에 영향 있는 것만 골라 분류한다
  3. 정해진 표 양식으로 리포트를 만들어 팀에 공유한다

여기서 매주 생기는 문제 세 가지입니다.

문제구체적으로
범위가 다르다담당자마다 훑는 곳이 다름
형식이 흔들린다분류가 "자본규제"였다 "자본 규제"였다, 영향도가 "높음"이었다 "상"이었다
바쁘면 건너뛴다주간 리포트가 격주가 되고, 어느새 안 함

범위 · 형식 · 실행 을 파일로 고정하면 이 셋이 모두 사라집니다. 이 차시는 그중 형식을 다룹니다.

관찰 포인트 — 두 결과에서 이 세 가지를 비교하세요

  1. 분류 이름 — "자본규제" vs "자본 규제" vs "건전성 규제"
  2. 영향도 값 — "높음/중간/낮음" vs "상/중/하" vs "High/Medium"
  3. 다음 행동 칸 — 구체적 행동인가, "검토 필요" 같은 빈 문장인가

대개 흔들립니다. AI가 잘못한 게 아니라, 우리가 형식을 약속하지 않았습니다. 표 두 개를 나란히 놓고 쓰려면 사람이 손으로 맞춰야 하고, 그러면 자동화가 아닙니다.

3. 개념 — 계약이 반복을 가능하게 합니다

3-1. 출력 계약이란

"결과에 이런 항목이 이런 값으로 나와야 한다" 를 미리 못 박은 것입니다. 자유 서술과의 차이는 이렇습니다.

자유 서술로 부탁

"표로 정리해줘. 컬럼은 제목/출처/분류/영향도…"

  • 매번 다르게 해석됩니다
  • 값의 종류가 제한되지 않습니다
  • 빈칸이 생겨도 그냥 넘어갑니다

계약으로 고정

항목·허용 값·필수 여부를 파일로 정의

  • 분류는 정해진 다섯 값 중에서만
  • 영향도는 높음/중간/낮음 세 가지만
  • 다음 행동은 필수 — 비면 다시 시도
  • 없는 항목을 지어내지 못함

이 실습 폴더에는 그 계약 파일이 이미 들어 있습니다. 열어서 확인합니다.

Claude Code 입력창에 붙여넣기

전문 용어 없이 쉬운 말로 설명해줘. 표로 정리해줘.

3-2. 계약이 생기면 따라오는 것

얻는 것왜
비교 가능지난주와 이번주를 나란히 놓을 수 있습니다
누적 가능같은 구조라 계속 쌓아 통계를 낼 수 있습니다
자동 검증필수 항목이 비면 기계가 잡아냅니다
다른 곳에 흘려보내기스프레드시트·메일·대시보드에 그대로 넣을 수 있습니다

하네스 4원리 중 세 번째 — 계약이 병렬성을 만든다
형식을 먼저 정하면 ① 여러 담당이 동시에 일해도 합칠 수 있고 ② 매주 같은 형식으로 반복할 수 있습니다. 3차시 Level 2에서 "담당자들이 서로 대화하지 않는데도 통합이 되는" 이유가 이것입니다.

4. 권한과 안전 — 자동으로 돌리기 전에

4-1. 대화형과 자동 실행은 다릅니다

대화형 (지금까지 한 것)자동 실행
사람보면서 승인없음
위험 통제승인 단계에서 막음샌드박스로만 막음
언제처음 해보는 일, 판단이 필요한 일세 번 이상 반복된, 검증된 일

4-2. 울타리는 셋 중에서 고릅니다

단계허용 범위언제 쓰나
읽기 전용파일을 읽기만. 아무것도 못 바꿈조사·분석·리뷰는 전부 여기
작업 폴더 쓰기지정한 폴더 안에서만 생성·수정결과 파일을 만들어야 할 때
전체 허용제한 없음이 과정에서는 쓰지 않습니다

자동화의 조건
① 세 번 이상 반복된 일만 자동화합니다. 자동화는 대화형의 대체가 아니라 충분히 반복된 일에 대한 졸업입니다.
② 처음에는 읽기 전용으로 시작합니다.
③ 결과를 사람이 받아 보는 자리를 반드시 남깁니다 (메일·채널·시트).

4-3. (선택) 실제 자동 실행 형태

Codex CLI 를 설치했다면, 계약을 걸어 자동 실행하는 실제 명령은 이런 모양입니다. 지금 실행할 필요는 없고, 형태만 보세요.

터미널 — 계약을 건 자동 실행 (참고)
codex exec --search --sandbox read-only \
  --output-schema schema/regwatch.schema.json \
  --output-last-message regwatch.json \
  "최근 1주 한국 금융 규제·공시를 조사해 schema에 맞춰 JSON으로 반환하라.
   분류와 영향도는 스키마에 정의된 값 중에서만 고르라."
🔎

핵심은 한 줄: --output-schema 가 계약을 겁니다. 결과가 계약을 벗어나면 자동으로 다시 시도합니다. 사람이 형식을 맞출 필요가 없어지는 지점이 여기입니다.

이 명령을 회사 스케줄러나 자동화 도구에 걸면 "매주 월요일 오전 8시 자동 발행" 이 됩니다. 여기까지 오면 만든 것은 "이번 주 리포트"가 아니라 리포트를 만드는 시스템입니다.

11개 중 2번(매체)과 9번(이슈 등급) 이 핵심입니다. 이 둘만 고정해도 지난주와 이번주를 나란히 놓고 볼 수 있습니다.

그리고 10번을 필수로 만든 것이 실무적으로 가장 큰 변화였습니다. 예전 리포트에는 "지속 모니터링 예정" 같은 문장이 절반이었는데, 필수로 걸어 두니 구체적 행동이 나오기 시작했습니다.

"사람이 확인하는 시점"을 30분으로 잡은 이유

예전에는 리포트 작성에 2시간 반, 검토에 10분이었습니다. 지금은 작성 10분, 검토 30분입니다. 총 시간은 3시간 → 40분으로 줄었지만, 검토 시간은 오히려 늘렸습니다.

이것이 자동화의 올바른 방향입니다 — 사람을 빼는 게 아니라 사람이 판단에만 시간을 쓰게 하는 것.

📌

6번 항목(CPA·ROAS 재계산)이 다음 차시의 재료입니다. 계산을 설명서로 시키면 틀립니다. 6차시에서 이 계산을 도구로 옮깁니다.

6. 스스로 점검

  • 계약 없이 돌렸을 때의 흔들림을 직접 봤다 (분류·영향도·행동 칸)
  • 내 업무 산출물의 항목을 표로 정의했다
  • 허용 값을 정할 수 있는 항목을 최소 하나 찾았다
  • output-contract.md 와 스키마 파일을 만들었다
  • 읽기 전용과 폴더 쓰기의 차이를 설명할 수 있다
  • 자동화해도 되는 조건("세 번 이상")을 안다

7. 더 해보기 (선택)

  • 계약 위반 실험 — 일부러 계약에 없는 항목을 요구해 보세요. AI가 거절하거나 다시 시도하는지 확인합니다.
  • 지난 결과와 비교 — 같은 계약으로 만든 결과 두 개를 주고 "전주 대비 변화" 를 정리하게 해보세요. 계약이 있어야 가능한 작업입니다.
