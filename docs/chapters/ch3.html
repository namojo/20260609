이 차시에서 배우는 것

  • 같은 결과물을 세 가지 방식으로 만들어 보고 차이를 표로 정리한다
  • "항상 팀이 낫다"가 왜 틀린지 비용으로 설명할 수 있다
  • 내 업무의 적정 단계를 근거와 함께 판정한다

1. 질문을 바꿉니다

많은 사람이 이렇게 묻습니다. "어느 AI가 제일 좋아요?" 실무에서 더 쓸모 있는 질문은 이것입니다.

"이 일은 몇 단계짜리 일인가?"

같은 "트렌드 분석 보고서" 라도, 오늘 오후 임원 미팅 전에 필요한 브리핑과 매달 나가는 정례 보고서는 완전히 다른 일입니다. 이 차시에서는 세 가지 방식을 직접 돌려 보고 그 감각을 익힙니다.

단계비유방식어울리는 상황
Level 1유능한 인턴 한 명지시 하나로 처음부터 끝까지오늘 오후 미팅 전 브리핑
Level 2분야별 전문가 팀나눠서 동시에 조사 + 취합 + 검증분기 심층 보고서
Level 3보고서 공장역할·규칙·양식을 파일로 자산화매달 반복되는 정례 보고

소재는 "디스플레이 × AI 트렌드 분석 보고서" 입니다. 가상의 전략마케팅팀이 되어 봅니다.

2. Level 1 — 인턴 한 명에게 맡기기

실습 폴더의 codex 안에서 시작합니다.

Windows · PowerShell
cd C:\harness-edu\codex; claude
macOS · 터미널
cd ~/harness-edu/codex && claude
Claude Code 입력창에 붙여넣기
너는 한국디스플레이 전략마케팅팀의 리서처야.
'디스플레이 × AI 최신 트렌드 분석' 보고서를 report/L1-brief.md 로 작성해줘.

다뤄야 할 범위:
1) 디스플레이 기술 — OLED·마이크로LED·QD, 최근 전시회 발표
2) AI와의 접점 — AI 글래스·XR 기기용 패널, 온디바이스 AI 수요, AI 공정·검사
3) 시장·경쟁 — 주요 패널사 동향과 수급 전망

규칙: 모든 수치·주장에 출처와 날짜를 붙이고, 마지막에 '전략적 시사점' 3가지와
'이번 분기 액션 제안'을 담아줘. 분량 2~3쪽.
👀

예상 결과: 5~10분 안에 report/L1-brief.md 초안이 나옵니다. 구조도 있고 문장도 매끄럽습니다. 충분히 쓸 만합니다.

🔎

관찰 포인트 — 두 가지 한계를 찾아보세요

  1. 깊이가 고르지 않습니다. 세 분야를 한 명이 훑다 보니 어느 하나는 얕습니다. 어느 쪽이 얕은지 표시해 두세요.
  2. 조사자와 검증자가 같은 사람입니다. 자기가 쓴 출처를 자기가 검사하면 오류가 잘 안 보입니다.

이 두 가지가 Level 2가 존재하는 이유입니다.

3. Level 2 — 전문가 팀에게 나눠 맡기기

이번에는 담당을 나눕니다. 조사 3명이 동시에 일하고, 집필자가 합치고, 검증자가 대조합니다.

Claude Code 입력창 — 비우고 시작
/clear
Claude Code 입력창에 붙여넣기
디스플레이 × AI 트렌드 분석 보고서를 팀으로 만들어줘.

[1단계] 조사 담당 3명을 동시에 띄워서 각자 research/ 폴더에 노트를 쓰게 해줘.
  - 기술 담당    → research/tech.md
  - AI 접점 담당 → research/ai.md
  - 시장 담당    → research/market.md
  셋 다 끝날 때까지 기다려줘.

[2단계] 집필 담당이 research/ 노트 3개를 하나의 보고서로 통합해서
  report/L2-report.md 로 써줘.

[3단계] 검증 담당이 보고서의 모든 수치·출처를 원문과 대조해서
  문제 항목을 [검증실패] 목록으로 보고하고, 집필 담당에게 수정시켜줘.
👀

예상 결과: 화면 아래에 담당자들이 나타나고 동시에 일합니다. research/ 에 노트 3개, report/L2-report.md 에 통합 보고서가 생깁니다. Level 1보다 오래 걸립니다.

🔎

관찰 포인트 세 가지

  1. 깊이 — 세 분야가 각각 전담이라 얕은 곳이 줄었습니다. Level 1에서 얕았던 분야를 다시 보세요.
  2. 검증 분리 — 집필자와 검증자가 다른 담당입니다. 자기 글을 자기가 검사할 때 생기는 편향을 구조로 막습니다. (4차시의 핵심 원리를 미리 만납니다)
  3. 합의된 양식이 필요합니다 — 담당자들은 서로 대화하지 않습니다. research/ 노트에 무엇을 어떤 형식으로 남길지 미리 정해져 있어야 통합이 매끄럽습니다.
💸

비용을 반드시 짚고 갑니다. 담당자가 늘면 사용량도 그만큼 늘어납니다. 급한 브리핑에 5명을 투입하는 것은 낭비입니다. 깊이가 비용을 정당화할 때만 팀을 씁니다.

4. Level 3 — 매달 돌아가는 시스템

Level 2까지는 "이번 보고서"를 만드는 방법이었습니다. Level 3은 질문이 바뀝니다.

"다음 달에도, 담당자가 바뀌어도, 같은 품질이 나오게 하려면?"

답은 더 좋은 프롬프트가 아니라 파일입니다. 그 실물이 이미 codex/ 폴더에 들어 있습니다. 열어서 확인합니다.

Claude Code 입력창에 붙여넣기
이 폴더의 AGENTS.md, .codex/agents/ 안의 파일들, .agents/skills/trend-report/SKILL.md 를
훑어보고 각각 무슨 역할인지 한 줄씩 정리해줘.
파일사람 조직에 비유하면담긴 것
AGENTS.md팀 업무 수칙 게시판출처 필수, 추측 금지 같은 불변 규칙
.codex/agents/ 5개직무기술서 5장누가 · 무엇을 · 어떤 기준으로
skills/trend-report/보고서 표준 양식 + 매뉴얼어떻게 — 템플릿 · 출처 표기 · 문체

이 구조가 있으면 매달 실행이 한 줄로 줄어듭니다.

Level 3의 매달 실행 (개념)
trend-report 스킬과 전문가 팀으로 2026년 7월호 보고서를 생산.
지난 호와 비교해 '전월 대비 변화' 섹션 포함.
🔎

가장 중요한 관찰: Level 1과 Level 3의 실행 명령은 둘 다 한 줄입니다. 차이는 명령의 길이가 아니라 그 한 줄이 기대고 있는 자산의 양입니다.

그리고 Level 3의 진짜 비용은 실행이 아니라 초기 설계에 있습니다 — 직무기술서와 템플릿을 쓰는 일. 사람 조직을 만들 때와 똑같습니다.

5. (선택) 같은 지시, 다른 도구

Codex CLI 를 설치한 분만 해보세요. Level 1과 똑같은 지시를 Codex에 넣습니다.

터미널에 붙여넣기 (codex 폴더에서)
codex exec --sandbox workspace-write --skip-git-repo-check "'디스플레이 × AI 최신 트렌드 분석' 보고서를 report/L1-codex.md 로 작성해라. 기술·AI접점·시장 3개 범위를 다루고, 모든 수치에 출처와 날짜를 붙이고, 전략적 시사점 3가지로 마무리해라."
🔎

관찰 포인트: 두 결과의 구성·강조점·표 형식이 다를 것입니다. 어느 쪽이 낫냐가 아니라 — 지시가 느슨하면 도구마다 다르게 해석한다는 사실이 중요합니다. 이 간극을 없애는 것이 2차시의 지식 파일이고, 5차시의 스펙입니다.

"왜 시스템화하지 않는가"를 직접 느껴 보기

  • "항상 팀이 낫다"가 틀린 이유를 비용으로 설명할 수 있다
  • Level 1과 Level 3의 실행 명령이 둘 다 한 줄인 이유를 안다
  • 내 업무의 적정 Level을 근거와 함께 정했다

흔한 실패와 대처

증상왜 생기나대처
Level 2에서 담당자가 안 나뉨에이전트 팀 기능 꺼짐설치가이드 3-5절 → 터미널 새로 열기
웹 조사 내용이 부실함검색 없이 아는 것만 씀"웹에서 최신 자료를 찾아서" 를 명시. 출처 없는 수치는 쓰지 않기
L2가 L1보다 나아 보이지 않음주제가 좁아 분업 이득이 적음정상입니다. 그 자체가 판단 근거 — 이 일은 L1짜리입니다
전부 Level 3이라고 판정이상적으로만 생각준비 비용을 다시 보세요. 설계에 드는 시간이 이득보다 크면 과잉입니다
