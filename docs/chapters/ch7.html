이 차시에서 처음 나오는 말

인수 기준
"이 정도면 됐다" 를 미리 정한 조건. 있어야 완성 여부를 다투지 않습니다.
교차 실행

회고
돌려 본 결과를 놓고 무엇을 고칠지 정하는 자리. 하네스는 한 번 만들고 끝이 아닙니다.

이 차시에서 배우는 것

  • 흩어진 조각을 하네스 한 벌로 조립한다
  • 다른 사람이 돌려 보게 해서 재현성을 검증한다
  • 실제 업무에 붙이는 30일 계획과 안전 조건을 정한다

1. 1차시 업무 지도를 다시 꺼냅니다

여섯 차시 전에 고른 그 업무입니다. 지금 다시 보면 판단이 달라졌을 수 있습니다.

그때 물었던 것지금 다시 답해 보기
이 업무의 위임 수준은?여전히 ⓑ 자동화 후보인가? 해보니 ⓐ 나 ⓒ 였나?
가장 귀찮은 부분은?실제로 AI가 덜어 준 부분이 그곳이었나?
🔴 로 분류한 자료는?그 자료 없이도 이 하네스가 돌아가는가?
🔎

판단이 바뀌었다면 그것이 이 과정의 성과입니다. 처음에는 "다 자동화하고 싶다" 였다가, 지금은 "여기는 사람이 봐야 한다" 를 구분할 수 있게 되었다면 제대로 배운 것입니다.

2. 조립 — 조각을 한 벌로

지금까지 만든 것들이 각각 하네스의 어느 자리에 들어가는지 확인합니다.

차시만든 것하네스에서의 자리
1차시업무 지도 · 안전 범위범위 — 무엇을 맡기고 무엇을 안 맡기나
2차시나의 업무 용어집Skill — 판단 기준·용어·금지 사항
3차시적정 Level 판정규모 — 담당자를 몇 명 둘 것인가
4차시에이전트 팀 + 검증자Agent — 누가 무엇을 맡나
5차시출력 계약형식 — 결과가 매번 같은 구조로
6차시Tool 후보Tool — 계산을 코드에 위임할 지점

이제 조립합니다. my-harness 폴더에서 Claude Code를 실행하세요.

Windows · PowerShell
cd C:\harness-edu\my-harness; claude
macOS · 터미널
cd ~/harness-edu/my-harness && claude
Claude Code 입력창에 붙여넣기 ① — 용어집을 스킬로
2차시에서 만든 나의_업무_용어집.md 를 이 하네스의 스킬로 넣어줘.
파일을 .claude/skills/ 아래 적절한 이름으로 배치하고,
어느 에이전트가 이 스킬을 참조해야 하는지도 정리해줘.
Claude Code 입력창에 붙여넣기 ② — 계약과 규칙 붙이기
5차시에서 만든 출력 계약(output-contract.md)을 이 하네스에 반영해줘.
그리고 CLAUDE.md 에 이 프로젝트의 불변 규칙을 정리해줘. 최소한 다음을 넣어줘.

- 원본 수치는 변경 금지
- 모르는 것은 지어내지 말고 [확인 필요] 로 표시
- 산출물은 output-contract 형식을 반드시 따를 것
- 최종 승인은 사람이 한다
👀

예상 결과: my-harness 안에 CLAUDE.md, .claude/agents/, .claude/skills/, output-contract.md 가 갖춰집니다. 이것이 하네스 한 벌입니다.

3. 검증 — 남이 돌려도 되는가

내가 만든 것이 나한테만 되는 것이면 자산이 아닙니다. 세 가지로 확인합니다.

인수 기준확인 방법
재현되는가같은 입력으로 두 번 돌려 구조가 같은가
빠뜨림이 없는가검증 담당이 항목을 하나씩 대조했는가
근거가 남는가어디서 온 값인지 추적할 수 있는가

3-1. 교차 실행 — 옆 사람과 바꿔 돌려 보기

가장 확실한 검증입니다. 내 하네스 폴더를 옆 사람에게 주고, 그 사람이 설명 없이 돌려 보게 합니다.

받은 사람이 입력창에 붙여넣기
이 폴더의 CLAUDE.md 와 .claude/ 구성을 읽고,
이 하네스가 무슨 일을 하는 것인지 파악한 다음,
아래 예시 데이터로 한 번 실행해줘.

[예시 데이터 2~3줄]
🔎

  • "이 용어가 무슨 뜻이죠?" → 용어집에 빠진 항목

4. 운영 — 실제 업무에 붙이기 전에

4-1. 실 데이터 적용 전 체크리스트

지금까지는 전부 가상 데이터였습니다. 실제 업무 자료를 넣기 전에 확인해야 할 것들입니다.

  • 이 하네스가 다루는 자료 중 🔴(개인정보·계약·미공개 실적)가 있는가
  • 있다면, 그 부분을 빼고도 업무가 되는가 (가명화·범위 축소)
  • 회사 규정상 이 도구 사용이 허용되는가 — 확인했는가
  • 결과물의 최종 승인자가 정해져 있는가
  • 틀렸을 때 누가 어떻게 발견하는가
  • 보안 프로그램을 우회하거나 끄지 않았는가
🔒

하나라도 확실하지 않으면 실 데이터를 넣지 마세요. 가상 데이터로 한 달 돌려 보고, 그동안 규정 확인을 받는 순서가 안전합니다. 급하게 붙였다가 생긴 사고는 되돌릴 수 없습니다.

4-2. 어디에 두고 누가 고치나

질문권장
어디에 보관하나개인 PC가 아니라 팀이 접근할 수 있는 곳 (공유 드라이브·사내 저장소)
누가 고치나담당자 1명을 정합니다. 아무나 고치면 아무도 신뢰하지 않습니다
언제 고치나정기 회고 시점 + 새 규칙이 생겼을 때
바뀐 걸 어떻게 아나변경 이력을 남깁니다 (날짜 · 무엇을 · 왜)

시점할 일완료 기준

시범		기존 방식과 병행. 하네스로 만든 리포트와 손으로 만든 리포트를 대조숫자 불일치 0건

팀 공유		팀 회의에서 5분 공유. 후배 1명이 혼자 실행해 보기질문 없이 완주

⑤ 1분 공유 — 정하늘 대리가 팀에 말한 것

팀 회의 5분 공유
저는 루미에르 주간 성과 리포트를 하네스로 만들었습니다.
담당자는 4명이고, 수치 검증 담당이 원본 파일과 리포트를 항목별로 대조합니다.
용어집 파일에 매체별 용어와 VAT 처리 규칙을, 계약 파일에 11개 리포트 항목을
고정해 두었습니다.
다음 달에는 예산 소진 페이스 계산기를 도구로 붙일 생각입니다.

작성 2시간 30분 → 40분으로 줄었고, 그중 검토가 30분입니다.
줄어든 건 작성 시간이고, 검토 시간은 오히려 늘렸습니다.
7주 동안 실제로 바뀐 것
  • 시간: 주 2시간 30분 → 40분 (연 90시간 절감)
  • 품질: VAT 오류·이슈 누락이 검증 담당에게 걸림
  • 인수인계: 휴가 때 후배가 폴더만 열면 됨 — 예전엔 인수인계 문서를 따로 썼음
  • 가장 큰 변화: 리포트의 "다음 행동" 칸이 "모니터링 예정" 에서 구체적 제안으로 바뀌었고, 광고주 미팅의 질문이 달라졌음
🔒

정하늘 대리는 실 데이터를 3주차부터 넣었습니다. 1~2주차는 지난 분기 데이터를 익명화해서 썼고, 그동안 회사 보안 담당에게 사용 승인을 받았습니다. 순서를 지킨 것이 핵심입니다.

5-1. 내 업무에 대입해 보기

완성도보다 구조를 갖추는 것이 목표입니다. 여섯 칸 중 넷만 채워져 있어도 하네스입니다.

6. 수료 점검

  • 내 업무 하네스가 파일로 존재한다
