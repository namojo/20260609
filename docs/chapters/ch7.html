트리거 경계
"이럴 땐 쓰고, 이럴 땐 쓰지 않는다" 를 적어 둔 것. 잘 만든 스킬의 표시입니다.

이 차시에서 배우는 것

  • 완성된 하네스를 가져다 그대로 돌려 본다
  • 그 안을 뜯어 1~6차시에서 배운 구조가 그대로 들어 있음을 확인한다
  • 내 업무에 맞게 고쳐 쓰고, 마지막엔 처음부터 만든다

1. 만들기 전에 — 남이 만든 것부터 봅니다

4차시에서 하네스 구성해줘 로 팀을 만들어 봤습니다. 그런데 이미 잘 만들어진 하네스가 100개 공개되어 있습니다. 처음부터 만드는 것보다 고쳐 쓰는 것이 훨씬 빠르고, 잘 만든 것을 보는 게 가장 좋은 공부입니다.

왜 이걸 지금 하나 — 1차시에 했으면 안 됐나?
안 됐습니다. 4차시에서 담당자가 일곱 명 나왔다가 다섯으로 줄여 보고, 검증 담당이 흡수돼 있는 것을 발견해 본 사람만 남의 하네스를 열었을 때 "왜 이 구성인지" 가 읽힙니다. 만들어 본 적이 없으면 그냥 파일 더미로 보입니다.
이번 차시의 목표는 하네스를 쓰는 법이 아니라 읽고 평가하고 고치는 법입니다.

2-2. 작업 폴더에 옮겨 심기

🗂️

폴더 이름은 영문으로 만듭니다. 아래에서 meeting·deck 같은 영문 이름을 쓰는 이유입니다 — 한글·공백이 섞인 경로는 일부 도구에서 인식이 실패해, 원인 찾기 어려운 오류로 이어집니다. 파일 내용은 얼마든지 한글로 써도 됩니다.

4. 실습 C — 내 업무용으로 고쳐 쓰기

남의 하네스는 남의 회사 기준으로 만들어져 있습니다. 그대로 쓰면 어색한 부분이 나옵니다. 그 부분을 고치는 것이 이식입니다.

Claude Code 입력창에 붙여넣기 — [ ] 안을 본인 조직에 맞게
이 하네스를 우리 팀 기준으로 고쳐줘.

우리 상황:
- 조직: [광고대행사 마케팅솔루션팀]
- 회의 성격: [매주 월요일 주간 캠페인 리뷰, 60분, 5명]
- 우리 양식: [회의록은 "결정사항 / 미결 / 액션(담당·기한)" 3단 구성]
- 우리가 쓰는 말: [매체, 캠페인, ROAS, 목표달성률]
- 빼도 되는 것: [경영진 보고용 요약 파트]

바꾼 내용을 파일별로 알려주고, 왜 그렇게 바꿨는지 한 줄씩 붙여줘.
👀

예상 결과: 회의록 템플릿이 우리 3단 양식으로 바뀌고, 90분 기준 시간 배분이 60분으로 조정되고, 안 쓰는 파트가 빠집니다. 새로 만든 게 아니라 고친 것이라 10분이면 됩니다.

사례 정하늘 대리의 이식 — 84번을 주간 리뷰 회의에 7차시 · 7주간의 결말

① 고른 이유

정 대리의 월요일은 이렇습니다. 오전에 주간 리포트를 만들고(2차시~6차시에서 하네스로 해결), 오후 2시에 팀 주간 리뷰 회의에 들어갑니다. 리포트는 자동이 됐는데 회의는 여전히 즉흥적이었습니다. 안건 없이 시작해 45분을 숫자 읽기에 쓰고, 정작 "그래서 카카오 예산을 어떻게 할 것인가" 는 "다음 주에 다시 보죠" 로 끝났습니다.

② 고친 것 세 가지

원본정 대리 버전
90분 기준 시간 배분60분으로 재배분 — 현황 10 / 논의 30 / 결정 15 / 정리 5
일반 회의록 템플릿팀 양식인 결정 / 미결 / 액션(담당·기한) 3단으로 교체
배경조사원이 웹을 뒤짐지난주 리포트(report/)를 먼저 읽도록 변경 — 우리 데이터가 이미 있으므로

③ 세 번째 수정이 진짜 이식이었다

앞의 둘은 형식이었습니다. 세 번째가 달랐습니다. 6차시까지 만든 리포트 하네스의 산출물이, 회의 하네스의 입력이 됩니다. 두 하네스가 report/2026-07-W3.md 파일 하나로 연결된 것입니다.

④ 3주 뒤

이전지금
리포트 작성2시간 30분20분 (검수 포함)
회의 시간60분 → 자주 초과45분에 끝남
"다음 주에 다시"매주 2~3건0~1건
회의록기억나면 작성회의 중 템플릿에 채움
왜 이렇게 했나

정 대리가 7주 동안 배운 것은 프롬프트 잘 쓰는 법이 아니었습니다. 반복되는 일에서 판단 기준을 꺼내 파일로 만드는 법이었습니다. 그래서 84번 하네스를 열었을 때, 그 안의 다섯 명과 세 개의 스킬이 낯설지 않았습니다. 처음 보는 하네스를 읽고 고칠 수 있게 된 것 — 그것이 이 과정의 진짜 결과물입니다.

한 가지 지켜줘 — 마지막 담당자는 반드시 검증 담당으로,
앞 사람 결과를 대조해 틀린 것을 찾아 되돌려 보내는 역할로 만들어줘.
👀

예상 결과: CLAUDE.md · .claude/agents/ · .claude/skills/ 가 갖춰집니다. 이것이 하네스 한 벌입니다. 3절에서 뜯어본 84번과 같은 구조인지 비교해 보세요.

💡

막히면 베끼세요. harness-100/ko/ 에서 비슷한 업무를 찾아 "이 하네스의 구조를 참고해서 내 업무용으로 만들어줘" 라고 하면 훨씬 좋은 결과가 나옵니다. 100개 목록은 저장소 README_ko.md 에 표로 있습니다.

6. 검증 — 남이 돌려도 되는가

내가 만든 것이 나한테만 되는 것이면 자산이 아닙니다. 세 가지로 확인합니다.

인수 기준확인 방법
재현되는가같은 입력으로 두 번 돌려 구조가 같은가
빠뜨림이 없는가검증 담당이 항목을 하나씩 대조했는가
근거가 남는가어디서 온 값인지 추적할 수 있는가

6-1. 교차 실행 — 옆 사람과 바꿔 돌려 보기

가장 확실한 검증입니다. 내 하네스 폴더를 옆 사람에게 주고, 그 사람이 설명 없이 돌려 보게 합니다.

받은 사람이 입력창에 붙여넣기

이 하네스가 무슨 일을 하는 것인지 파악한 다음,
아래 예시 데이터로 한 번 실행해줘.

[예시 데이터 2~3줄]
🔎

관찰 포인트 — 받은 사람이 이런 질문을 한다면 그 부분이 빠진 설명입니다.

  • "결과가 이게 맞아요?" → 인수 기준이 없음
  • "이 용어가 무슨 뜻이죠?" → 용어집에 빠진 항목

7. 운영 — 실제 업무에 붙이기 전에

7-1. 실 데이터 적용 전 체크리스트

지금까지는 전부 가상 데이터였습니다. 실제 업무 자료를 넣기 전에 확인해야 할 것들입니다.

  • 이 하네스가 다루는 자료 중 🔴(개인정보·계약·미공개 실적)가 있는가
  • 있다면, 그 부분을 빼고도 업무가 되는가 (가명화·범위 축소)
  • 회사 규정상 이 도구 사용이 허용되는가 — 확인했는가
  • 결과물의 최종 승인자가 정해져 있는가
  • 틀렸을 때 누가 어떻게 발견하는가
  • 보안 프로그램을 우회하거나 끄지 않았는가
🔒

하나라도 확실하지 않으면 실 데이터를 넣지 마세요. 가상 데이터로 한 달 돌려 보고, 그동안 규정 확인을 받는 순서가 안전합니다. 급하게 붙였다가 생긴 사고는 되돌릴 수 없습니다.

7-2. 어디에 두고 누가 고치나

질문권장
어디에 보관하나개인 PC가 아니라 팀이 접근할 수 있는 곳 (공유 드라이브·사내 저장소)
누가 고치나담당자 1명을 정합니다. 아무나 고치면 아무도 신뢰하지 않습니다
언제 고치나정기 회고 시점 + 새 규칙이 생겼을 때
바뀐 걸 어떻게 아나변경 이력을 남깁니다 (날짜 · 무엇을 · 왜)

8. 선택 확장 — 표지 이미지 스킬 만들어 발표자료까지

여기부터는 선택입니다. ChatGPT Plus 구독과 Codex CLI 설치가 되어 있어야 합니다. 안 되어 있으면 건너뛰어도 과정 수료에 지장이 없습니다.

13번 presentation-designer 하네스는 발표 구성과 내용을 만들어 주지만, 표지 이미지는 못 만듭니다. Codex에는 이미지 생성 도구가 내장돼 있으니, 그것을 부르는 스킬을 직접 만들어 붙입니다.

8-1. codex-image 스킬 직접 만들기

발표자료 하네스 심기 · Windows
mkdir C:\harness-edu\my-work\deck
Copy-Item -Recurse C:\harness-edu\harness-100\ko\13-presentation-designer\.claude C:\harness-edu\my-work\deck\
cd C:\harness-edu\my-work\deck
claude
발표자료 하네스 심기 · macOS
mkdir -p ~/harness-edu/my-work/deck
cp -r ~/harness-edu/harness-100/ko/13-presentation-designer/.claude ~/harness-edu/my-work/deck/
cd ~/harness-edu/my-work/deck
claude
Claude Code 입력창에 붙여넣기
.claude/skills/codex-image/SKILL.md 를 만들어줘.

이 스킬이 하는 일: Codex CLI 의 내장 이미지 생성 도구를 불러
발표자료용 이미지를 만들고 images/ 폴더에 저장한다.

실행 명령은 이 형태다:
codex exec --sandbox workspace-write --skip-git-repo-check "이미지 생성 도구로 '<장면 설명>' 이미지를 만들고 ./images/<파일명>.png 로 저장해라. 저장 경로만 한 줄로 보고."

SKILL.md 에 반드시 넣을 것:
1. description — "발표자료 표지·섹션 이미지가 필요할 때 사용" 처럼
   언제 쓰는지가 분명하게. 이게 유일한 트리거다.
2. 장면 설명 작성 규칙 — 사람 얼굴·특정 기업 로고·실존 인물은 요청하지 않는다,
   글자는 이미지에 넣지 않는다(깨진다), 스타일을 한 단어로 고정한다
3. 슬라이드 종류별 권장 스타일 (표지 / 섹션 구분 / 배경)
4. 저장 규칙 — images/ 아래, 슬라이드 번호를 파일명에 넣는다
5. 쓰지 않을 때 — 차트·표·다이어그램은 이미지 생성이 아니라 슬라이드로 그린다

파일만 만들고, 실행은 아직 하지 마.
👀

예상 결과: .claude/skills/codex-image/SKILL.md 가 생깁니다. 2차시에서 만든 용어집과 같은 형태의 파일입니다 — 맨 위에 name 과 description, 아래에 규칙. 스킬은 결국 잘 쓴 문서 하나입니다.

🔎

만든 뒤 description 한 줄만 다시 읽으세요. 이 문장이 스킬의 유일한 트리거입니다. "이미지 관련 작업" 처럼 두루뭉술하면 아무 때나 불리고, 너무 좁으면 필요할 때 안 불립니다. 6차시에서 도구 설명문이 트리거였던 것과 정확히 같은 원리입니다.

8-2. 발표자료 만들어 보기

Claude Code 입력창에 붙여넣기
다음 내용으로 10장짜리 발표자료를 만들어줘.

제목: [3분기 캠페인 성과와 예산 재배분 제안]
대상: [광고주 마케팅 담당 임원 3명]
시간: [15분]
핵심 메시지: [목표는 달성했지만 카카오 비중을 줄여야 한다]
근거 데이터: [W3 통합 ROAS 366.9%, 목표 대비 104.8%,
            카카오모먼트 163%로 크게 미달, 전주 대비 CPA +13.1%]

표지와 섹션 구분 슬라이드의 이미지는 codex-image 스킬로 만들고,
숫자는 차트와 표로 그려줘.
마지막에 발표 노트도 붙여줘.
👀

예상 결과: 스토리보드 → 슬라이드 → 이미지 생성 → 발표 노트 → 검수 순으로 진행됩니다. images/ 에 표지 이미지가 저장되고, 슬라이드 문서에서 그 파일을 참조합니다. 이미지 생성만 Codex가 하고 나머지는 Claude Code가 합니다 — 도구를 섞어 쓴 것입니다.

⚠️

이미지 생성 시 주의

  • 실존 인물·특정 기업 로고·경쟁사 제품을 만들지 마세요. 대외 자료에 쓰면 문제가 됩니다
  • 생성 이미지에 글자를 넣지 마세요 — 한글은 거의 깨집니다. 글자는 슬라이드에서 얹습니다
  • 생성물은 장식입니다. 판단 근거가 되는 숫자는 반드시 차트·표로
  • 사내 대외 자료 규정에 AI 생성 이미지 표기 의무가 있는지 확인하세요

9. 수료 점검

  • harness-100에서 하나를 골라 내려받고 그대로 돌려 봤다
  • 그 안의 agents/ · skills/ 가 배운 구조임을 확인했다
  • 내 조직 기준으로 고쳐 봤다 (양식 · 용어 · 입력)
  • 1차시 업무로 처음부터 하네스를 하나 만들었다
  • 만든 것을 남에게 돌려보게 하고 피드백을 반영했다
  • 실 데이터 적용 전 보안 체크리스트를 통과했다
  • (선택) 스킬을 직접 만들어 다른 도구(Codex)를 붙여 봤다

Claude Code 입력창에 붙여넣기

전문 용어 없이, 팀장이 읽고 바로 판단할 수 있게 써줘.

10. 마무리 — 7주 뒤에 남는 것

AI에게 일을 시키는 법을 배운 게 아닙니다. 내 일에서 판단 기준을 꺼내 파일로 만드는 법을 배웠습니다.
기준이 파일에 있으면 — 결과가 재현되고, 남에게 넘길 수 있고, 틀린 곳을 고칠 수 있습니다. 그것을 못 하면 아무리 좋은 모델도 매번 다른 답을 줍니다.

가져가면 좋은 세 가지 습관

습관언제

결과를 믿기 전에 대조숫자 하나라도 원본과 맞춰 봅니다. 6차시의 교훈입니다
