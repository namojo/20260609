1. 이 문서는 무엇인가

이 과정에서 우리는 AI에게 일을 한 번 시키는 것이 아니라, 여러 번 같은 품질로 시키는 구조를 만듭니다. 그 구조를 하네스(Harness) 라고 부릅니다. 하네스를 만들려면 세 가지가 필요합니다.

필요한 것왜이 문서에서
Claude Code하네스가 실행되는 작업장. 터미널에서 대화하는 AI설치 + 로그인
에이전트 팀 기능전문가 여러 명이 동시에 일하게 하는 스위치환경변수 1줄
Harness 플러그인"하네스 구성해줘" 한마디로 팀을 설계해 주는 도구플러그인 설치

여기에 실습 파일(생산 보고서 엑셀, 샘플 데이터 등)이 담긴 저장소를 내 노트북으로 받아 오면 준비가 끝납니다.

이 문서를 끝내면 다른 설치가이드의 "설치 전 확인"은 모두 통과한 상태가 됩니다. macOS를 쓰신다면 이 문서 대신 공통 준비 — macOS 를 보세요.

이 과정에서 설치하지 않는 것: Node.js, bun, Docker, WSL2, 별도 편집기.
Claude Code는 자체 실행 파일로 설치되므로 개발 언어 런타임이 필요하지 않습니다. (Python은 3번째 설치가이드 MCP 서버 에서만 씁니다.)

2. 설치 전 확인

항목필요한 것확인·대처
운영체제Windows 10 (1809 이상) 또는 113-2절에서 winver 로 확인
구독Claude Pro / Max / Team / Enterprise무료 플랜은 Claude Code를 쓸 수 없습니다
저장 공간2GB 이상 여유Claude Code 약 500MB + Git 약 400MB + 실습 파일
관리자 권한필요 없음Claude Code는 내 사용자 폴더에 설치됩니다
인터넷claude.ai · github.com 접속 가능사내망에서 막히면 문제 해결 ⑥
선행 설치없음이 문서가 모든 가이드의 출발점
🔑

구독을 먼저 확인하세요. claude.ai 로그인 → 왼쪽 아래 계정 메뉴에서 플랜을 봅니다. Free 라고 적혀 있으면 이 과정의 실습을 진행할 수 없습니다.

API Key는 필요하지 않습니다. 구독 계정으로 브라우저 로그인만 하면 됩니다. 회사 계정(Team/Enterprise)이라면 관리자가 Claude Code 사용을 허용했는지 미리 확인하세요.

실습 자료 규칙 — 실습 폴더에는 가상 데이터만 넣습니다. 실제 고객명·주민등록번호·계약금액이 담긴 파일은 복사해 오지 않습니다. AI 도구는 그 폴더의 파일을 읽을 수 있습니다.

3. 설치 절차

3-1. PowerShell 여는 법 (모든 명령의 출발점)

[시작] 버튼(창문 모양) → 검색창에 아래를 입력 → Enter

검색창에 입력
PowerShell
👀

예상 결과: 파란색 또는 검은색 창이 열리고 맨 아랫줄이 PS C:\Users\본인이름> 으로 끝납니다.

이 PS C:\Users\본인이름> 을 프롬프트라고 부릅니다. 뒤에 명령을 붙여넣고 Enter를 누르는 것이 전부입니다. 관리자 권한으로 열 필요는 없습니다.

복사·붙여넣기 하는 법 (앞으로 계속 씁니다)
회색·검은 블록 오른쪽의 [복사] 버튼을 누르고 → PowerShell 창을 클릭 → Ctrl+V → Enter.
붙지 않으면 마우스 오른쪽 버튼 한 번을 누르세요(옛 방식 창에서는 우클릭이 붙여넣기입니다).

💡

명령을 실행하면 커서가 한동안 멈춘 것처럼 보일 수 있습니다. 다운로드 중이니 끝날 때까지 기다리세요. 프롬프트(PS C:\...>)가 다시 보이면 끝난 것입니다.

3-2. Windows 버전 확인

PowerShell에 붙여넣기
winver
👀

예상 결과: "Windows 정보" 작은 창에 Windows 10 또는 Windows 11, 버전 22H2 같은 표시. [확인] 으로 닫습니다.

⚠️

이렇게 나오면 오류: Windows 8.1 이하이면 Claude Code가 동작하지 않습니다 — 교육 담당자에게 문의하세요.

3-3. Git for Windows 설치

먼저 이미 깔려 있는지 확인합니다.

PowerShell에 붙여넣기
git --version
👀

예상 결과: git version 2.55.0.windows.1 형태. 버전이 보이면 이미 설치된 것이므로 3-4절로 넘어갑니다.

인식되지 않으면 아래로 설치합니다.

PowerShell에 붙여넣기
winget install --id Git.Git -e --source winget
👀

예상 결과: 진행률 표시가 흐르고 마지막에 설치 완료 또는 Successfully installed. 2~5분 걸립니다.

⚠️

이렇게 나오면 오류: 'winget' 용어가 ... 인식되지 않습니다 → 문제 해결 ③ (설치 파일을 직접 받는 방법)

설치가 끝나면 PowerShell 창을 완전히 닫고(오른쪽 위 X) 3-1번 방법으로 새로 엽니다. 그리고 다시 git --version 으로 확인합니다.

왜 새 창이 필요한가: 설치 프로그램이 명령의 위치를 시스템에 등록했지만, 이미 열려 있던 창은 그 변경을 모릅니다. 이 단계를 건너뛰어 생기는 오류가 초보자 오류 1위입니다.

Git이 왜 필요한가: ① 실습 저장소를 받아 오고(git clone), ② 플러그인을 GitHub에서 내려받는 데 쓰이고, ③ Windows에서 Claude Code가 파일 작업을 할 때 함께 설치되는 Git Bash를 사용합니다. 공식 문서도 Windows에서 Git for Windows 설치를 권장합니다.

3-4. Claude Code 설치

PowerShell에 붙여넣기
irm https://claude.ai/install.ps1 | iex
👀

예상 결과: 다운로드 진행 표시가 흐르고 Claude Code installed successfully 같은 문장이 나옵니다. 1~3분.

⚠️

이렇게 나오면 오류: 'irm'은(는) 내부 또는 외부 명령이 아닙니다 → PowerShell이 아니라 명령 프롬프트(CMD)를 열었습니다. 프롬프트 맨 앞에 PS 가 붙어 있어야 PowerShell입니다.

여기서도 PowerShell 창을 닫고 새로 엽니다. 그리고 확인합니다.

PowerShell에 붙여넣기
claude --version
👀

예상 결과: 2.1.211 (Claude Code) 형태의 버전 번호. 숫자가 달라도 됩니다.

⚠️

이렇게 나오면 오류: 'claude' 용어가 ... 인식되지 않습니다 → 문제 해결 ② (경로 등록)

업데이트는 신경 쓰지 않아도 됩니다. 이 방식으로 설치하면 Claude Code가 백그라운드에서 스스로 최신 버전으로 갱신합니다.

3-5. 에이전트 팀 기능 켜기 (하네스 필수 조건)

하네스는 전문가 에이전트 여러 명이 팀으로 협업하는 기능을 씁니다. 이 기능은 기본이 꺼져 있어 한 번 켜 주어야 합니다.

PowerShell에 붙여넣기
setx CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS 1
👀

예상 결과: 아래 한 줄만 나옵니다.

예상 화면
성공: 지정한 값을 저장했습니다.

이 설정은 새로 여는 창부터 적용됩니다. PowerShell을 닫고 새로 열어 값을 확인하세요.

PowerShell에 붙여넣기
echo $env:CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS
👀

예상 결과: 1 한 글자. 아무것도 안 나오면 새 창에서 다시 확인하고, 그래도 비어 있으면 setx 명령을 다시 실행하세요.

설정 파일로 켜는 방법도 있습니다 — 이 저장소의 settings.json 처럼 %USERPROFILE%\.claude\settings.json 의 env 항목에 "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1" 을 넣어도 동일합니다. JSON 문법을 틀리면 설정 전체가 무시되므로, 처음이라면 위의 setx 방법을 쓰세요.

3-6. 실습 저장소 받기 (실습 폴더 만들기)

실습 파일(생산 보고서 엑셀, 샘플 CSV, 과제 문서)이 담긴 저장소를 내 노트북으로 받습니다.

☁️

바탕 화면이나 문서 폴더에 받지 않습니다. 회사·개인 PC 대부분에서 OneDrive 폴더 백업이 켜져 있어, 바탕 화면과 문서 폴더가 클라우드 동기화 폴더로 바뀌어 있습니다. 그 안에 저장소를 받으면 이런 일이 생깁니다.

  • 실습 파일이 OneDrive로 계속 업로드되어 느려지고 용량을 잡아먹습니다
  • 동기화가 파일을 잠가 "다른 프로그램이 사용 중" 오류가 납니다
  • 탐색기에서는 보이는데 터미널 경로와 실제 경로가 달라 AI가 파일을 못 찾습니다

그래서 이 과정은 C 드라이브 바로 아래(C:\harness-edu)에 받습니다. 드라이브 루트는 OneDrive 백업 대상이 아니어서 위 문제가 원천적으로 생기지 않고, 경로가 짧아 입력·확인도 쉽습니다.

PowerShell에 붙여넣기
git clone https://github.com/namojo/harness-edu.git C:\harness-edu
👀

예상 결과: 아래처럼 진행되고, C:\harness-edu 폴더가 생깁니다. 탐색기 주소창에 C:\harness-edu 를 넣으면 바로 열립니다.

예상 화면
Cloning into 'C:\harness-edu'...
remote: Enumerating objects: 300, done.
Receiving objects: 100% (300/300), 6.20 MiB | 4.10 MiB/s, done.

경로에 OneDrive 가 없는지 확인하세요. 있으면 잘못 받은 것입니다.

⚠️

이렇게 나오면 오류

  • already exists and is not an empty directory → 이미 받아 둔 것이므로 그대로 다음으로 넘어갑니다
  • could not resolve host → 네트워크 차단입니다 (문제 해결 ⑥)
  • Permission denied / 액세스가 거부되었습니다 → 회사 정책으로 C 드라이브 루트 쓰기가 막힌 경우입니다. 아래처럼 사용자 폴더에 받으세요. 이후 나오는 모든 C:\harness-edu 를 이 경로로 바꿔 읽으면 됩니다
루트가 막힌 경우에만
git clone https://github.com/namojo/harness-edu.git "$env:USERPROFILE\harness-edu"

이제 그 폴더로 이동합니다. 실습은 항상 이 폴더 안에서 합니다.

PowerShell에 붙여넣기
cd C:\harness-edu; pwd
👀

예상 결과: 현재 위치가 출력됩니다. 이 줄에 OneDrive 도, Desktop 도 없어야 정상입니다.

예상 화면
Path
----
C:\harness-edu

사용자 폴더로 받은 경우에는 C:\Users\이름\harness-edu 가 나옵니다. 둘 다 정상입니다.

⚠️

이미 바탕 화면에 받았다면 지금 옮기세요 → 문제 해결 ⑦. 그대로 두면 실습 중간에 동기화 충돌로 막힐 수 있습니다.

플러그인이 뭔가요: Claude Code에 기능을 얹는 확장입니다. Harness 플러그인은 "어떤 전문가 팀을 만들어야 하는가"를 설계해 주는 도구이고, document-skills 는 엑셀·워드·PPT 파일을 직접 읽고 만드는 능력을 더합니다.

7. 문제 해결

① 'git' 용어가 ... 인식되지 않습니다

  • 원인: Git 설치가 안 됐거나, 설치 전부터 열려 있던 창을 그대로 쓰고 있습니다.
  • 해결: ⑴ PowerShell 창을 모두 닫고 새로 열어 git --version 재확인 → ⑵ 그래도 안 되면 PC 재부팅 → ⑶ 여전하면 설정 → 앱 → 설치된 앱 에서 Git 검색. 없으면 3-3절을 다시 합니다.

② 'claude' 용어가 ... 인식되지 않습니다

  • 원인: 설치는 됐지만 명령 경로(PATH)가 아직 반영되지 않았습니다.
  • 해결 1: PowerShell을 닫고 새로 열어 다시 claude --version.
  • 해결 2: 그래도 안 되면 아래를 한 번 실행한 뒤, 창을 새로 엽니다.
PowerShell에 붙여넣기
$claudePath = "$env:USERPROFILE\.local\bin"
$userPath = [Environment]::GetEnvironmentVariable("Path", "User")
if ($userPath -notlike "*$claudePath*") {
    [Environment]::SetEnvironmentVariable("Path", "$userPath;$claudePath", "User")
}
👀

예상 결과: 아무 메시지 없이 프롬프트로 돌아옵니다. 터미널에서는 "조용한 성공"이 정상입니다. 새 창에서 claude --version 이 동작합니다.

③ 'winget' 용어가 ... 인식되지 않습니다

  • 원인: Windows 앱 설치 관리자(App Installer)가 없거나 오래된 Windows 10입니다.
  • 해결: Git 설치 파일을 직접 받습니다. 브라우저 주소창에 아래를 붙여넣고 → 다운로드 → 모든 화면 기본값 그대로 Next → Install → Finish.
주소창에 붙여넣기
https://git-scm.com/downloads/win
⚠️

다운로드 주소를 꼭 확인하세요. 검색 결과 상단 광고 링크에서 가짜 설치 파일을 받는 사고가 실제로 발생합니다. 주소가 git-scm.com 인지 확인하고, SmartScreen 경고가 뜨면 추가 정보 → 실행.

④ 로그인은 됐는데 "구독이 필요합니다" 라고 나옵니다

  • 원인: 무료 플랜 계정으로 로그인했습니다. Claude Code는 Pro 이상이 필요합니다.
  • 해결: Claude Code 입력창에서 /logout → 다시 claude 실행 → 구독 계정으로 로그인. 회사 계정이면 관리자에게 Claude Code 사용 허용 여부를 확인하세요.

⑤ /plugin marketplace add 가 실패합니다

  • 확인 1: PowerShell에서 git --version 이 동작하는지 (플러그인은 Git으로 내려받습니다).
  • 확인 2: 저장소 이름을 정확히 입력했는지 — revfactory/harness, anthropics/skills.
  • 확인 3: 사내 방화벽이 github.com 을 막고 있을 수 있습니다. 휴대폰 테더링으로 바꿔 재시도해 보세요.

⑥ 다운로드가 멈추거나 "연결할 수 없음"이 뜹니다

  • 원인: 사내 프록시·방화벽·백신이 접속을 막거나 회선이 일시적으로 끊겼습니다.
  • 해결: ⑴ 브라우저에서 https://claude.ai 와 https://github.com 이 열리는지 확인 → ⑵ 사내 Wi-Fi 대신 휴대폰 테더링으로 재시도(교육장에서 가장 빠른 방법) → ⑶ 설치 명령은 여러 번 재실행해도 안전합니다(↑ → Enter) → ⑷ 계속 막히면 백신을 임의로 끄지 말고 IT 담당자에게 문의.

⑦ 이미 바탕 화면(OneDrive)에 받았습니다 / 폴더를 찾지 못합니다

  • 원인: OneDrive 폴더 백업이 켜져 있으면 바탕 화면의 실제 위치가 C:\Users\이름\OneDrive\바탕 화면 으로 바뀝니다. 그 안에 저장소를 두면 동기화가 .git 파일을 잠가 "다른 프로그램이 사용 중" 오류가 나고, 실습 파일이 계속 업로드됩니다.
  • 해결: 아래를 붙여넣으면 동기화되지 않는 C:\harness-edu 로 옮깁니다. 옮길 것이 없으면 그렇게 알려 줍니다.
PowerShell에 붙여넣기
$dst = "C:\harness-edu"
$found = @([Environment]::GetFolderPath("Desktop"), "$env:USERPROFILE\Desktop", "$env:USERPROFILE\Documents", $env:USERPROFILE) |
         ForEach-Object { Join-Path $_ "harness-edu" } |
         Where-Object { $_ -ne $dst -and (Test-Path $_) } | Select-Object -Unique
if (-not $found) { "옮길 것이 없습니다. 현재 위치를 확인하세요: $dst" }
elseif (Test-Path $dst) { "이미 $dst 가 있습니다. 남은 사본은 직접 확인하세요: $($found -join ', ')" }
else { Move-Item -LiteralPath $found[0] -Destination $dst; "옮김: $($found[0])  ->  $dst" }
👀

예상 결과: 옮김: ... -> C:\harness-edu 한 줄. 그 뒤 cd C:\harness-edu 로 들어가면 됩니다.

⚠️

"사용 중" 오류로 옮겨지지 않으면: Claude Code를 /exit 로 닫고, 작업 표시줄의 OneDrive 아이콘 → 동기화 일시 중지(2시간) 후 다시 실행하세요. 그래도 안 되면 PC를 재부팅한 직후 실행합니다.
C 드라이브 루트 쓰기가 막혀 있으면 위 스크립트의 $dst 를 "$env:USERPROFILE\harness-edu" 로 바꿔 실행하세요.

왜 옮겨야 하나: 이 과정은 AI가 실행한 폴더의 파일을 읽고 씁니다. 그 폴더가 동기화 중이면 ① 파일 잠금으로 쓰기가 실패하고 ② 탐색기 경로와 실제 경로가 달라 "파일이 없다"는 오류가 반복됩니다. 처음부터 C:\harness-edu 에 두는 것이 가장 확실한 해결입니다.

⑧ 에이전트 팀이 만들어지지 않습니다

  • 확인: 새 PowerShell 창에서 echo $env:CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS 가 1 인지.
  • 해결: 비어 있으면 3-5절을 다시 하고 반드시 창을 새로 열어 claude 를 실행합니다. 이미 실행 중인 Claude Code에는 적용되지 않습니다.

⑨ 한글이 깨져 보입니다

  • 해결: Windows 11의 터미널(Windows Terminal) 로 여세요. 시작 → 터미널 검색 → 실행. 표시만 깨지는 것이고 동작에는 문제가 없습니다.

A. 자동 점검 스크립트 (설치 후 확인용 · 권장)

위 절차를 마친 뒤, 빠진 게 없는지 한 번에 점검하는 스크립트입니다. 빠진 항목만 설치하며, 여러 번 실행해도 안전합니다.

B. winget 으로 Claude Code 설치

본문의 설치 스크립트가 사내 정책으로 막힐 때 씁니다. 단, 자동 업데이트가 되지 않아 직접 갱신해야 합니다.

PowerShell에 붙여넣기
winget install Anthropic.ClaudeCode

갱신은 winget upgrade Anthropic.ClaudeCode.

C. 이 과정에서 쓰지 않는 것

  • WSL2 · Docker: 이 과정의 실습은 Windows에서 그대로 동작합니다. 설치하지 마세요.
  • npm 설치: Node.js 22 이상이 이미 있는 분만 npm install -g @anthropic-ai/claude-code 로 대체할 수 있습니다. Node.js를 새로 깔 필요는 없습니다.
  • Claude 데스크탑 앱: 터미널 없이 쓰는 GUI 버전입니다. 이 과정은 터미널 기준으로 진행하므로 필수가 아닙니다.
